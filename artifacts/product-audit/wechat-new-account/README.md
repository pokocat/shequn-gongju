# 新建微信号弹窗审查

审查对象：`?view=pc&module=wechat` → `新建微信号`

## 证据截图

1. `01-awaiting-authorization.png`：待扫码授权状态。
2. `02-authorized-form.png`：授权后自动回填并解锁表单状态。

## 流程步骤

1. 打开微信管理，点击“新建微信号”。
2. 查看左侧二维码、授权状态和右侧锁定表单。
3. 点击“确认已扫码授权”，观察账号信息自动回填。
4. 继续填写绑定人、安全资料、紧急联系人和归属信息。
5. 点击“确认录入”，完成账号入库。

## 发现与建议

### P0 · 必须优先修复

1. **确认录入没有真正的必填校验**。页面提示“必填项标记 *”，但授权后按钮直接可用；微信号、绑定人、地区等关键字段为空时仍可能提交。建议按字段定义校验，并在对应字段下显示错误原因。
2. **确认录入没有明确的成功反馈**。当前交互关闭弹窗即可结束，用户看不到“已入库”、生成编号、库存状态或下一步操作。建议保存后显示结果提示，并定位到新账号行或打开账号详情。
3. **授权状态仍是前端确认按钮**。真实接入时需要二维码过期、刷新、扫码中、授权成功、授权失败、取消授权和超时状态；按钮只能作为本地演示回调，不能作为生产状态来源。

### P1 · 影响效率和准确性

1. **底部操作栏遮挡滚动内容**。授权后截图中，右侧紧急联系人区域与底部“取消/确认录入”区域发生视觉覆盖；长表单在小屏高度下不容易确认是否已看完。建议让右侧内容区预留底部安全间距，或让底部栏属于右侧滚动容器并保持不遮挡。
2. **表单缺少进度和完成度**。当前把多个业务阶段放在一个长表单内，用户不知道还有多少字段、哪些字段属于当前任务。建议保留“授权 → 账号资料 → 安全资料 → 归属确认”的步骤指示，并显示“已完成 x / y 项”。
3. **归属字段仍可自由输入**。项目、归属员工、会员负责人、部门和地区应优先使用已有项目/员工/地区数据源，避免手填产生重名、错配，尤其是地区与客服自动继承规则。
4. **二维码区域缺少有效期和刷新反馈**。建议显示二维码有效倒计时、刷新按钮、刷新后的状态提示，并在二维码失效时阻止继续授权。
5. **授权失败和重新扫码没有数据清理策略**。重新扫码后旧的自动回填资料仍可能留在表单状态中，存在把上一账号资料带入下一账号的风险。建议重新授权时清空授权字段，或明确标记“待新授权覆盖”。

### P2 · 可用性与安全体验

1. **敏感字段只有提示，没有可控查看机制**。密码、身份证号和银行卡号建议加入显示/隐藏控制、脱敏规则、权限说明和查看审计记录。
2. **紧急联系人只有姓名输入**。既然联系人是微信联系人，建议改为联系人搜索/选择，并显示头像、微信号、关系和二维码状态，避免只填同名文本。
3. **补充头像或微信二维码区域当前更像静态提示**。建议提供上传、替换、删除和格式校验反馈，并支持授权头像与人工上传头像的来源标识。
4. **部分辅助文字偏小**。二维码说明、敏感字段提示和联系人补充说明接近 10px，在高缩放和低对比度环境下可读性不足，建议提高到至少 12px 或提供更强对比度。
5. **取消时没有未保存提示**。填写了敏感资料后直接关闭容易误操作，建议在有修改时二次确认“放弃本次录入”。

## 审查边界

截图可以确认布局、层级、遮挡、可见状态和操作文案；无法仅凭截图确认真实微信扫码回调、接口失败重试、权限控制、敏感字段审计日志和后端入库一致性，这些需要接口联调与权限测试补充。
