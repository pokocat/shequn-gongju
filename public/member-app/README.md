# 主理人公社 · 会员小程序页面总览（设计交付）

共 **41 个页面 / 147 屏**（同一页面的不同状态各算一屏）。

## 怎么打开

双击 `index.html` 就能看。**如果缩略图是空白的**，那是浏览器拦了本地 `file://` 的内嵌页面，
在本文件夹里开一个终端跑：

    python3 -m http.server 8000

然后浏览器打开 http://localhost:8000 。单个页面（`pages/*.html`）直接双击一定能看。

## 这些页面是什么

不是重画的效果图，是**小程序的真实代码渲染出来的**——WXML 结构、WXSS 样式、
组件里的图标与插画都是线上那一份，脚本只把 `rpx` 换算回 px、把小程序标签换成
HTML 标签。所以你在这里量到的字号、间距、颜色，就是线上的值。

- **画布 430 × 932**，即 iPhone 14 Pro Max，与设计稿画布同尺寸。
  换算关系：小程序里 1px 设计稿 = 1.744rpx，这里已经换算回来了，**你量到的数就是设计稿的数**。
- **顶部状态栏与右上胶囊是微信原生渲染的**，页面不能占用那块区域。画出来是为了让你看到
  自绘头部真正可用的高度从哪开始。
- **底部 TabBar 是自定义组件**（不是原生 tabBar），中间抬起的宝石圆钮落点是会员卡页。
- 每个单页顶部有「切换整页 / 一屏」：**一屏** = 手机上一眼能看到的范围（可滚动）；
  **整页** = 整屏内容全部展开，方便通览与截图。

## 能点的地方

**跨页跳转是真的能点的**，和小程序里一样：

- 列表行、卡片、「查看全部 ›」这类入口
- 底部 TabBar 五格
- 子页左上角的返回键
- 页面顶部的页签（如「我的微信群 / 公告与活动」）

**点不动的是页内状态**：弹层、手风琴、筛选条、表单输入、播放。它们没有可静态解析的
落点，所以导出时接不上——但这些状态本身都在，作为该页面的**变体**列在
`shell.html` 右下角的页面清单里（如「微信群 · 活动详情弹层」「设置 · 注销账号弹层」）。
从清单进就能看到。

## 文字和数字是演示数据

版式、层级、状态是真的；**姓名、金额、班级名、时间都是编的**，不要当业务事实引用。
几处刻意的「留白」也不是漏画，是产品上的决定（例如邀请页没有「预计收益」、
续费页没有「AI 建议」、社群页没有「活跃度 92%」）——这些读数在系统里没有事实来源，
编一个出来会被运营当真拿去汇报。同理界面里不出现「AI / 智能匹配」字样：
报告是服务老师人工写的。

## 目录

- `index.html` —— 总览，按业务域分组，点缩略图进单屏
- `pages/*.html` —— 单屏，文件名即页面名，`--` 后面是状态名（如 `group--社群广场`）
- `css/app.css` —— 全局样式（由小程序 app.wxss + 各组件样式换算而来）
- `assets/` —— 插画与图片原件

## 想改样式怎么办

`css/app.css` 与每个单页 `<style>` 里的值都是**从小程序代码生成的**，
改这里不会回到小程序，下次重新导出也会被覆盖。要落到产品上，把结论给到开发即可
（改的是小程序仓库 `apps/member-app/miniprogram` 下的 wxss）。

## 这份导出是怎么来的（给开发看）

源码在小程序仓库 `apps/member-app/tools/design-export/`，页面或样式改动后重新生成：

    node apps/member-app/tools/design-export/build.js

生成后 `tools/design-export/missing.txt` 会列出缺字段与写错的图标名——**那里有内容就说明
导出里有一块是空的**，先修再发。守卫 `apps/member-app/test/design-export.test.js`
会拦住「新加了页面但没补演示数据」这种情况。
