# 主理人小程序消息首页：服务角色会话中枢

**日期：** 2026-10-05  
**范围：** 仅限主理人身份打开的小程序消息首页，不涉及 PC、其他身份端及主理台/团队/资产的详情页改造。

## 目标

将当前以“公告中心 / 通知消息”分类的消息入口改造成以服务角色会话为核心的消息首页。主理人的审核、经营提醒、课程提醒、资产通知、社群待办、订单状态与系统通知，均由对应角色通过会话传递和承接。

## 页面信息结构

1. 顶部应用头：主理人公社、简短状态描述、搜索入口。
2. 置顶会话区：仅展示存在未读消息、待处理动作、异常或临近事件的服务角色。
3. 全部会话区：展示其余服务角色，按最新消息时间倒序排列。
4. 底部导航：保留现有消息、发现、主理台、我的结构。

首页不设置独立待办宫格、经营数据卡或功能入口。所有需要处理的事项应在角色会话预览中明确说明“发生了什么”和“下一步要做什么”。

## 服务角色定义

| 角色 | 覆盖的业务事件 | 会话内操作 |
| --- | --- | --- |
| 经营教练 | 今日经营简报、经营诊断、目标提醒 | 查看简报、确认目标、进入经营详情 |
| 团队管家 | 团长/代理申请、成员变更、团队提醒 | 审核申请、查看团队、联系成员 |
| 增长顾问 | 招募线索、推广活动、转化建议 | 查看线索、进入推广、查看效果 |
| 资产助手 | 收益、结算、余额与异常 | 查看资产、确认结算、提现 |
| 课程顾问 | 训练营、导师、课程、直播和回看 | 查看课程、报名、进入直播或回看 |
| 社群运营官 | 群待回复、群活跃和运营提示 | 进入群运营、查看话题、发布任务 |
| 订单助手 | 订单、支付与售后状态 | 查看订单、处理售后 |
| 系统服务通知 | 订阅提醒和系统级通知 | 开启或管理服务提醒 |

## 排序与状态规则

- 有待办、未读、审核、风险或临近事件的会话进入置顶区。
- 置顶区内部优先级为：审核/风险 > 时效性任务 > 未读提醒 > 其他更新。
- 全部会话按最近消息时间倒序排列。
- 未读数量以品牌紫色数字徽标展示；审核、风险、超时等需要关注的会话以琥珀色强调；正常或已完成信息使用低对比灰色。
- 每行会话包括角色头像、角色名、职责标签、最后一条消息、时间以及未读数/状态标记。

## 交互与数据映射

- 点击角色会话行进入对应的角色对话页；对话流中的操作卡承接审核、查看团队、进入课程、查看资产等动作。
- 首页本轮仅搭建会话列表和进入入口，不重构这些详情功能。
- 现有公告和个人通知将被映射为角色会话事件：例如课程提醒进入课程顾问、工单更新进入社群运营官或系统服务通知、订单变更进入订单助手。
- 服务订阅从底部横幅收敛为“系统服务通知”角色会话。
- 无角色消息时展示清晰的空状态；加载失败继续复用现有错误条与重试能力。

## 视觉规范

- 继续沿用当前小程序的暖奶油背景、紫色品牌信号、琥珀色关注态、圆角卡片与字号体系。
- 教练、顾问、管家等角色使用真人或人格化头像；资产、订单、系统角色使用工具型头像。
- 所有头像右下角叠加短职责标签，如“经营”“团队”“课程”。
- 角色会话应保持信息密度可扫读：主标题为角色名，正文只保留一条行动导向的最新消息。

## 验收标准

1. 主理人消息首页以服务角色会话列表为唯一核心入口。
2. 页面存在清晰的置顶会话和全部会话层级，无独立任务宫格。
3. 团队、经营、课程、资产、社群、订单和系统通知均有明确角色归属。
4. 未读、审核/风险和正常状态的层级可一眼区分。
5. 服务通知订阅以系统服务通知会话呈现，不再使用独立底部横幅。
6. 页面继续支持加载、空状态、错误重试和既有底部导航。
7. 仅修改主理人小程序消息页相关文件，不修改 PCLayout 或其他页面。
