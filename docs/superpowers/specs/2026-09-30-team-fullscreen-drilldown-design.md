# 团队整屏下钻页面设计规格

日期：2026-09-30

## 1. 目标

将主理人公社小程序团队页中“我的团队”、运营网络卡片和影响力详情表格的下钻交互，从底部抽屉统一改造为独立整屏页面流。

改造后，用户可以在完整页面内浏览团队总览、关系成员、数据明细、成员详情和下一级关系；所有既有影响力指标、数值与角色权限口径保持不变。

## 2. 范围

本次仅改造 `public/member-app/pages/tasks.html` 中代理端与团长端的团队相关下钻交互。

覆盖入口：

- 团队页“我的团队”；
- 影响力详情表格的可点击数字单元格；
- “旗下运营网络”或“我的社群与推荐”卡片；
- 整屏成员列表中的成员行；
- 数据明细页中的成员行。

不覆盖履约、经营、推广、招募海报及现有独立页面的业务逻辑。

## 3. 整屏页面模型

### 3.1 我的团队总览

点击“我的团队”进入团队总览。页面包含：

- 顶部返回导航与标题；
- 团队总人数、圆环构成图和成员类型图例；
- 关系范围筛选：代理端为“全部、直推、团队、推荐”，团长端为“全部、直推、推荐、发展”；
- 成员类型筛选；
- 可搜索的成员列表；
- 当前身份对应的直属可运营或关系只读提示。

### 3.2 关系成员页

点击直属团长、发展代理、推荐关系、成员的下一级关系后，进入对应关系列表。

页面包含：

- 当前关系路径；
- 当前范围总人数；
- 搜索与分类筛选；
- 成员列表；
- 下钻箭头；
- 只读聚合范围说明。

直属范围可以显示可运营标识；发展、推荐范围只显示授权范围内的成员或聚合结果。

### 3.3 数据明细页

点击影响力详情表格的任意数字单元格后，进入与该单元格对应的整屏明细。

页面包含：

- 动态标题，由关系层级和指标名称组成；
- 当前总量与本周新增信息；
- 时间筛选：今日、本周、本月；
- 关系范围筛选；
- 搜索框；
- 日期分组的数据列表；
- 成员详情入口。

含新增值的指标优先以“新增关注”“新增扫码”“新增体验”“新增 VIP”等新增明细形态展示；普通人数、社群数和潜在人数组合以对应成员或社群来源明细展示。

### 3.4 成员详情页

点击成员进入成员详情。页面包含：

- 头像、姓名、身份和关系标签；
- 所属社群、关系说明、加入时间、地区等基础信息；
- 当前角色可见范围内的团队与行为汇总；
- “查看下一级关系”入口；
- 推荐和发展关系的只读说明。

## 4. 导航和状态

使用页面级状态栈替代当前 `TEAM_DETAIL_STACK` 抽屉状态。

每个页面状态包含：

- 页面类型：团队总览、关系成员、指标明细、成员详情；
- 标题；
- 关系范围；
- 指标名称；
- 上级成员或来源上下文；
- 路径面包屑；
- 当前筛选与搜索值。

返回操作只回退一个整屏状态，并恢复前页的筛选和滚动位置。关闭抽屉行为被移除。

## 5. 视觉与交互

- 整屏覆盖当前主理台内容区，不使用暗色遮罩、底部圆角抽屉或上拉动画；
- 顶部使用轻量小程序式导航；
- 白色内容面、暖米色背景、紫色主强调与现有页面一致；
- 统计区域采用圆环图、细分图例和轻量分割线；
- 成员列表采用头像、身份标签、两行说明、关键数值和右箭头；
- 搜索与筛选在数据密集页面保持固定且低干扰；
- 无数据和无权限时显示明确状态，不用空白代替权限说明。

## 6. 数据与权限边界

- 影响力表的列头、数字、潜在标识和新增数据不改动；
- 代理端直属团队可展示可运营标识，发展和推荐关系仅展示授权聚合；
- 团长端直属社群可展示可运营标识，推荐和发展关系仅展示授权聚合；
- 不展示超出当前角色授权范围的成员详情、履约、库存或财务数据；
- 本原型中的姓名、明细时间和档案字段为演示数据，仅用于展示下钻结构。

## 7. 实现边界

- 复用现有原生 JavaScript 渲染和事件委托模式；
- 在 `tasks.html` 内建立整屏详情层、页面状态栈、统一渲染函数和事件委托；
- 移除团队详情抽屉容器、样式和抽屉事件逻辑；
- 保留身份切换时关闭详情页并重置详情状态的行为；
- 不引入新的第三方依赖。

## 8. 验证标准

- “我的团队”进入整屏总览，而非弹窗或抽屉；
- 运营网络卡片、影响力表格数字、成员行均进入匹配的整屏页面；
- 成员详情和下一级关系可以连续下钻并逐级返回；
- 代理端与团长端显示各自的关系范围与权限提示；
- 页面在 430px 移动视口下无横向溢出；
- 内联脚本语法检查、`git diff --check` 和 `npm run build` 通过。
