# 平台模式两层配置设计

## 目标

将一人公司系统的平台模式配置迁移为两层结构：平台预置规则与运营可调参数。保持公司角色 D1-D3、代理角色 D4-D5 的统一等级体系，并明确管理员 / D1 的唯一配置权限。

本次补充代理与团长的能力继承关系：代理直接复用团长的社群运营能力，同时拥有团长管理、库存履约与经营管理等专属能力。

## 角色体系

### 公司角色

- D1：创始人
- D2：核心合伙人
- D3：事业合伙人

### 代理角色

- D4：分公司负责人
- D5：分公司合伙人

D1-D5 是平台统一身份等级，不允许在业务页面新增、删除、重排或改名。角色分类、层级关系和基础权限由平台初始化配置提供。

## 两层配置模型

### 第一层：平台预置规则

预置规则在小程序上线初始化时生成，属于平台身份与治理基础，不参与日常经营编辑。

包含：

- D1-D5 角色编码、名称和所属角色组
- 公司角色 / 代理角色分组
- 角色层级顺序与上下级关系
- 角色基础权限边界
- 招募与归属关系
- 可招募的下级角色范围
- 订单、库存、发货、佣金等核心业务归属原则
- 配置权限：仅管理员 / D1 可管理平台规则

预置规则只能通过平台版本升级或管理员执行受控的规则迁移变更。业务身份不可修改这部分内容。

### 第二层：运营可调参数

运营参数建立在预置规则之上，由管理员 / D1 在平台模式配置中维护。参数修改采用草稿、预览、发布、生效、审计流程。

包含：

- 各等级分润比例或佣金比例
- 招募名额与业务额度
- 申请审核方式和审核节点开关
- 晋升指标、考核周期和达标阈值
- 活动周期、任务周期和运营截止时间
- 低库存、待审核、待履约等业务预警阈值
- 可展示权益、培训内容和推广素材范围

运营参数不得改变 D1-D5 的身份骨架、角色归属方向和核心订单履约责任。

## 代理与团长功能继承

### 能力原则

```text
代理能力 = 团长基础社群能力 + 代理专属经营管理能力
团长能力 = 社群运营能力 + 推广成交能力 + 佣金查看能力
```

代理可直接经营自己的社群，因此不应只看到团长管理和库存履约功能。代理进入“社群”工作区时，直接复用团长社群能力与同一套操作入口；数据范围切换为代理自己负责的社群与成员。

### 共享社群能力

代理与团长均可使用以下能力：

- 查看并经营自己的社群
- 管理社群成员
- 发布内容和活动
- 领取或使用推广素材
- 跟进意向成员
- 推广商品
- 提供成交服务
- 查看成交订单的路由状态
- 查看社群数据与推广进度

### 代理专属能力

代理在共享社群能力之外，额外拥有：

- 招募团长
- 审核团长申请
- 查看和管理直属团长
- 向团长下发素材、活动和培训任务
- 管理进货与库存
- 接收团长成交订单并完成发货
- 处理物流、售后和低库存预警
- 查看销售回款、库存价值、经营利润和团长经营数据

### 团长专属展示

团长不显示代理专属的团队、库存和履约操作，只展示：

- 推广任务与素材
- 自己社群的成员和成交数据
- 已路由至上级代理的订单状态
- 预计佣金、已结算佣金与待结算佣金
- 向直属代理汇报社群运营数据

### 工作台导航

```text
代理工作台
├── 社群：复用团长社群运营能力，经营代理自己的社群
├── 团长：招募、审核、直属团长管理、任务下发
├── 履约：库存、待发货订单、物流、售后
└── 经营：回款、库存价值、经营利润、团队经营数据

团长工作台
├── 社群：我的社群、成员、内容、活动与成交服务
├── 推广：素材、推广任务、商品推广与成员跟进
├── 订单：成交订单路由状态与售后进度查看
└── 佣金：预计、待结算与已结算佣金
```

代理和团长使用一致的社群能力组件、卡片层级和交互方式；仅通过角色和数据范围决定是否展示代理专属导航、入口、经营数据和可执行动作。

## 权限规则

| 身份 | 查看预置规则 | 修改预置规则 | 查看运营参数 | 编辑 / 发布运营参数 |
|---|---:|---:|---:|---:|
| 平台管理员 | 是 | 受控管理 | 是 | 是 |
| D1 创始人 | 是 | 否，除非具备管理员权限 | 是 | 是 |
| D2 核心合伙人 | 是 | 否 | 是 | 否 |
| D3 事业合伙人 | 是 | 否 | 是 | 否 |
| D4 分公司负责人 | 仅查看相关规则 | 否 | 仅查看自身适用参数 | 否 |
| D5 分公司合伙人 | 仅查看相关规则 | 否 | 仅查看自身适用参数 | 否 |

管理员与 D1 的关系采用“身份 + 权限”双重判断：D1 仅在账号同时拥有平台配置权限时可编辑，不因等级名称自动获得所有系统管理权限。

## 配置页面信息架构

```text
平台建设
└── 模式配置
    ├── 配置总览
    │   ├── 当前模式与版本
    │   ├── 当前生效状态
    │   ├── 两层规则说明
    │   └── 最近变更
    ├── 平台预置规则
    │   ├── 公司角色 D1-D3
    │   ├── 代理角色 D4-D5
    │   ├── 归属与招募关系
    │   └── 核心业务责任
    ├── 运营可调参数
    │   ├── 分润与佣金
    │   ├── 审核与招募
    │   ├── 晋升与考核
    │   ├── 预警阈值
    │   └── 培训与推广
    └── 版本与变更记录
```

普通身份进入页面时保持同一信息架构，但进入只读态：隐藏保存、发布、回滚操作，仅显示当前生效值、适用范围、规则版本和自身适用权益。

## 数据流与生效规则

```text
平台初始化
→ 生成预置规则
→ 管理员 / D1 编辑运营参数草稿
→ 参数校验与影响预览
→ 发布配置版本
→ 到达生效时间
→ 新业务读取新版本
→ 历史订单按下单时生效版本结算
```

配置版本至少记录：版本号、修改人、修改时间、生效时间、影响模块、变更摘要和回滚来源。

## 边界与约束

- 不新增第二套等级编号，不将 G1-G5 与 D1-D5 并列展示。
- 不允许 D2-D5 修改平台规则或运营参数。
- 代理复用团长社群能力，不代表代理拥有团长佣金结算视图；代理应显示经营利润与销售回款。
- 团长不能执行进货、库存、发货、物流、售后、直属团长管理和团长审核。
- 运营参数的修改不能把团长 / 代理的履约责任转移给公司角色，也不能改变已产生订单的结算规则。
- 代理角色页面只展示其适用参数，不展示无权限修改控件。
- 当前阶段先实现前端配置结构、权限状态和版本化交互；后端持久化与真实鉴权接口沿用现有项目能力另行接入。

## 验收标准

- 配置总览明确区分“平台预置规则”和“运营可调参数”。
- D1-D5 始终以公司角色 D1-D3、代理角色 D4-D5 分组展示。
- 管理员 / 具备配置权限的 D1 可编辑、预览、发布和回滚运营参数。
- D2-D5 可以查看适用规则，但没有编辑、保存、发布和回滚入口。
- 代理进入社群页可执行与团长一致的社群运营操作，并展示代理自己的社群数据。
- 代理工作台额外显示团长、履约与经营模块；团长不显示这些代理专属模块。
- 团长只展示自身社群、推广、订单路由状态与佣金相关数据。
- 规则版本、生效时间和变更记录可见。
- 页面布局和交互风格与 aiopc-app 的平台建设 / 模式配置保持一致。
- 不影响现有代理招募、团长归属、库存发货和团长佣金业务语义。
