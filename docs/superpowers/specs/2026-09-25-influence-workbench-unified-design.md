# 影响力工作台一体化设计规格

日期：2026-09-25

## 1. 目标

将社群、团长、代理统一纳入影响力工作台，在保留现有“我的影响力”参考布局和底部运营商表单的前提下，实现影响力指标、关系范围、运营商资料和成员关系操作的联动。

## 2. 页面结构

页面按以下顺序组织：

1. 影响力总览：影响人数、预计收入、身份和当前数据范围。
2. 预计收入分析：保留现有收入构成图和金额说明。
3. 影响力详情：按直接运营、发展网络、推荐网络展示人数和新增变化。
4. 社群·团长·代理统一关系区：三类实体并列展示，可切换关系范围。
5. 旗下运营商：保留直属、推荐、其他运营商统计入口。
6. 运营商表单：保留姓名、身份、直属关系、负责社群和编辑入口，并根据当前身份动态展示字段。
7. 成员关系处理：保留 AI 识别结果、人工状态、采用 AI 结果和保存人工状态操作。

## 3. 关系范围

### 3.1 直接运营

直接运营范围只展示当前身份直接负责的社群、直属团长、直属代理和对应运营数据，可进入详情和执行允许的操作。

### 3.2 发展网络

代理可以查看自己发展的代理、下属代理发展的团长、团长旗下社群和聚合经营数据。发展网络中的非直属对象只读，不能替代直属团长管理、库存、采购、发货和售后操作。

团长不显示代理发展网络。

### 3.3 推荐网络

代理和团长都可以查看自己推荐的人、推荐人发展的团长及对应社群聚合。推荐网络只展示聚合数据，不展示无关链条，也不授予管理权限。

## 4. 交互联动

- 点击社群、团长或代理卡片，更新当前关系范围和影响力详情。
- 关系区的直接、发展、推荐筛选与影响力详情表同步。
- 影响力详情选中对象后，运营商表单展示对应身份和关系字段。
- 直属对象可进入详情或执行允许操作；发展、推荐对象仅显示聚合结果。
- 代理显示库存履约和经营数据；团长显示推广成交和佣金数据。
- 团长成交订单继续自动路由至直属代理库存，代理负责履约。
- 所有成员关系状态操作继续支持 AI 结果与人工结果对比，并明确保存来源。

## 5. 表单字段

代理：姓名、身份、直属团长数、负责社群数、履约范围、资料状态。

团长：姓名、身份、所属代理、运营社群数、推荐人数、佣金状态、资料状态。

普通成员：姓名、会员身份、所属社群、推荐关系、会员等级、资料状态。

发展网络和推荐网络对象不开放编辑，仅显示“只读聚合”。

## 6. 数据边界

- 使用现有 `memberNetworkScope` 的 direct、development、recommendation 关系语义。
- 直接运营数据与聚合数据分开计算，禁止通过前端隐藏字段代替权限判断。
- 代理库存、采购、发货和售后明细不进入团长可见范围。
- 非本人推荐链路下的社群、团长和成员不进入当前影响力结果。
- 关系状态变更只影响当前选中对象，不改变角色层级和归属关系。

## 7. 验证标准

- 影响力页面保留参考图核心排版和底部运营商表单。
- 代理可在同一页面看到社群、团长、代理三类关系和发展/推荐聚合。
- 团长可在同一页面看到自己的社群、推荐人、推荐团长和社群聚合，但看不到代理履约明细。
- 点击关系卡片、筛选项和详情对象会同步更新页面数据。
- AI/人工关系状态操作继续可用。
- `npm run build`、类型检查、脚本检查和浏览器回归通过。
