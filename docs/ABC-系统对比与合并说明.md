# 社群管理 A / B / C 对比与合并说明

## 合并结论

统一版本以「私域系统紫色版本」为唯一主系统。B 与 C 是这套系统的连续演进，C 的信息架构为最新基线；A 不再独立演进，其微信群三视图能力已迁入主系统。

## 能力对比

| 范围 | 社群管理 A | 社群管理 B | 社群管理 C | 统一版本 |
| --- | --- | --- | --- | --- |
| 产品定位 | 单项目微信群管理 | 跨项目私域运营中台 | B 的信息架构收敛版 | 跨项目私域社群运营中台 |
| 视觉体系 | 黑白 + 荧光绿 | 深色紫蓝 PC + 双小程序 | 延续 B | 延续 B/C |

| 微信群管理 | 运营列表、状态看板、主从详情 | 列表、卡片、大区与用途规则 | 延续 B | A 三视图 + B/C 业务规则 |
| 微信资源 | 基础归属微信 | 个人/企微、列表/卡片、右侧编辑 | 延续 B | 保留 |

## 已合并原则

1. 只保留一个代码主线：`私域系统紫色版本`。
2. 微信群管理一级显示形式统一为「运营列表 / 状态看板 / 主从详情」。
3. 运营列表内部继续提供列表与卡片二级切换。
4. 三种显示形式共享同一筛选条件、项目上下文、群数据和成员名单入口。
5. 大区、招商号/客服号、容量预警、群主交接和成员入群状态以 B/C 规则为准。
6. 会员运营采用 C 的收敛结构，不恢复为多个侧边栏页面。

## 后续工程边界

当前仍是前端交互原型，模拟数据分散在组件中。进入真实开发前，应把项目、微信账号、员工、群、成员、任务和回访记录抽成统一领域模型，并接入持久化 API；否则跨页面新增或编辑在刷新后仍会重置。
