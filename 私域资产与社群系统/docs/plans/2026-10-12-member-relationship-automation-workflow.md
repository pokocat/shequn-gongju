# 会员个微/企微自动化关系闭环实施计划

日期：2026-10-12
设计文档：`docs/superpowers/specs/2026-10-12-member-relationship-automation-design.md`

## 实施目标

在不改变会员主表现有布局的前提下，把个微和企微“添加”升级为可追踪的自动化任务入口，并在会员详情中提供任务状态、AI判断、人工复核、关系状态、风险摘要和历史记录。当前仓库未发现现成自动化服务客户端，因此先实现可替换的服务适配层和本地演示适配器；真实环境只需替换 API 实现，不把外部服务地址、密钥或执行逻辑写进页面组件。

## 任务 1：建立自动化领域模型与适配器

### 文件

- 新建 `src/app/data/relationshipAutomation.ts`

### 内容

1. 定义自动化任务类型：
   - `AutomationTaskStatus`
   - `AiReviewStatus`
   - `HumanReviewStatus`
   - `RelationshipAutomationTask`
   - `PersonalAddTaskInput`
   - `EnterpriseAddTaskInput`
   - `HumanReviewInput`
2. 定义任务创建、查询、人工确认的服务接口。
3. 提供稳定的任务状态排序和关系结果映射函数。
4. 提供本地演示适配器：
   - 每次创建生成唯一任务 ID；
   - 不执行真实微信操作；
   - 模拟待执行、执行中、AI判断和待人工复核状态；
   - 保留任务数据，便于页面在没有后端连接时演示完整流程。
5. 适配器不得写入真实账号密钥，不得记录敏感凭证。

### 验证

- 类型检查通过；
- 同一会员连续创建三次得到三个不同任务；
- 个微和企微输入字段分别完整；
- 人工复核能返回最终关系状态。

## 任务 2：建立会员关系任务状态管理

### 文件

- 修改 `src/app/components/InfluenceRanking.tsx`

### 内容

1. 引入自动化领域模型和适配器。
2. 在组件状态中增加：
   - 关系任务记录；
   - 当前任务创建状态；
   - 当前查看的任务；
   - AI判断状态；
   - 人工复核状态；
   - 人工备注和失败原因。
3. 保留现有 `recordManualAction`，将它定位为人工操作日志，不再作为个微/企微添加的唯一执行结果。
4. 增加统一任务创建函数：
   - 个微调用 `createPersonalAddTask`；
   - 企微调用 `createEnterpriseAddTask`；
   - 每次按钮点击创建一条独立任务；
   - 创建成功后增加执行次数并写入任务日志；
   - 创建失败时保留人工登记入口并提示错误。
5. 任务结果通过适配器回写，页面关闭后再次打开可根据会员和关系账号恢复任务摘要。
6. 处理任务状态幂等和状态前进规则，避免旧结果覆盖人工确认结果。

### 验证

- 主表四个个微/企微添加按钮都进入自动化任务创建逻辑；
- 连续点击三次能产生三条任务记录；
- 关注和入群按钮不受影响；
- 状态下拉和原有人工日志入口继续可用。

## 任务 3：重构个微/企微添加弹窗为任务执行面板

### 文件

- 修改 `src/app/components/InfluenceRanking.tsx`

### 内容

1. 保留现有表格布局和角色顺序。
2. 个微面板展示：
   - 会员基本信息；
   - 目标关系角色；
   - 执行账号和人员；
   - 所属群；
   - 群内添加、搜索微信号、二维码三种方式；
   - 最近任务摘要；
   - 执行按钮和任务状态。
3. 企微面板展示：
   - 企业微信账号；
   - 服务人员；
   - 会员微信号；
   - 复制账号；
   - 打开添加引导；
   - 发起企微添加；
   - 最近任务摘要。
4. 按状态切换按钮：
   - 添加；
   - 执行中；
   - AI识别中；
   - 待复核；
   - 再次添加；
   - 已通过；
   - 风险处理。
5. 禁止执行中的同一任务重复提交，但允许明确点击“再次添加”创建新任务。

### 验证

- 个微三种方式均能创建任务；
- 企微发起添加能创建任务；
- 复制微信号失败时不影响任务创建；
- 弹窗关闭、再次打开、切换会员后状态正确。

## 任务 4：增加 AI 判定和人工复核交互

### 文件

- 修改 `src/app/components/InfluenceRanking.tsx`
- 如需拆分，再新增 `src/app/components/RelationshipTaskReview.tsx`

### 内容

1. 在任务面板展示：
   - 自动化执行状态；
   - AI判定状态；
   - AI建议结果；
   - 置信状态或结果说明；
   - 人工复核状态。
2. 当任务进入待复核时显示：
   - 确认已申请；
   - 确认已通过；
   - 确认未通过；
   - 确认被拒绝；
   - 确认已拉黑；
   - 无法添加。
3. 提供人工字段：
   - 失败原因；
   - 备注；
   - 是否继续尝试；
   - 下一次处理时间；
   - 转交人员。
4. 人工确认结果优先于普通 AI 回写，并同步更新关系状态、人工日志和下一步操作提示。
5. 保留 AI 原始判断，不允许人工修改覆盖原始 AI 证据。

### 验证

- AI疑似结果进入待人工复核；
- 人工确认后关系状态、次数和日志同步更新；
- 人工确认结果不会被重复普通回调覆盖；
- 失败原因和备注可在历史记录中查看。

## 任务 5：增加关系摘要、风险和历史记录

### 文件

- 修改 `src/app/components/InfluenceRanking.tsx`
- 如需纯函数测试，新增 `src/app/data/relationshipAutomation.test.ts`

### 内容

1. 在关系对象区域展示：
   - 总执行次数；
   - 成功次数；
   - 失败次数；
   - 待复核次数；
   - 连续未通过次数；
   - 最近执行时间；
   - 最近失败原因。
2. 增加关系完成度和当前主任务摘要。
3. 连续未通过达到 3 次时展示风险预警：
   - 更换添加方式；
   - 转交其他服务人员；
   - 人工联系；
   - 暂停自动化尝试。
4. 增加任务历史面板，按时间倒序展示每次任务的自动化、AI和人工结果。
5. 对空任务、API失败、任务超时和没有人工复核记录提供明确空状态。

### 验证

- 历史记录不被新任务覆盖；
- 统计与任务记录一致；
- 3次连续失败出现风险提示；
- 主任务随关系状态变化。

## 交付边界

本次只改会员经营工作台前端和本地适配层，不创建真实外部 API 密钥，不伪造已连接的自动化服务，不实现微信客户端控制程序。真实 API 接入时，通过环境配置和适配器替换完成，页面组件不需要改变。

## 完成标准

- 个微和企微点击一次创建一次独立自动化任务；
- 任务状态、AI判断和人工确认完整可见；
- 关系最终状态正确更新；
- 添加次数和历史记录准确；
- 多次失败能产生风险提示；
- 现有会员表格布局和关注/入群操作不回归；
- 测试、构建和差异检查通过。
