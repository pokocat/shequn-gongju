# 行业生态运营台式页面设计规范

## 目标

将行业生态 / 平台管理页面调整为运营台式工作区，复用运营台的对象选择、指标概览、快捷操作和上下文详情逻辑，同时保留生态、SaaS、平台、项目及账号权限模型。

## 范围

仅修改 `src/app/components/EcosystemManagement.tsx` 的展示和交互层，不改变账号、身份、Scope、项目绑定、通讯工具分配和资源创建权限的数据结构。独立账号资产中心不在本次范围内。

## 页面框架

- 左侧保持生态树：生态、SaaS 合作伙伴、平台按层级展开。
- 右侧作为当前对象运营工作区：顶部对象摘要、核心指标、快捷操作、合作范围、身份账号和运营记录。
- 点击左侧对象只切换右侧上下文，不进行页面跳转。
- 账号详情、资源配置、邀请审核和风险处理均在当前页面内的抽屉或弹层完成。

## 右侧工作区

### 对象头部

展示对象名称、对象类型、运营状态、当前身份和更多操作入口。主要操作使用强调色，编辑和配置使用描边按钮，危险操作使用警示色。

### 指标概览

使用四个紧凑指标卡，展示当前对象相关的 SaaS、平台、项目和账号数据。指标卡只承担判断作用，点击后触发对应的当前页面内操作或打开详情区域。

### 快捷操作

统一采用图标加中文短文案：

- 查看平台：`LayoutDashboard`
- 查看项目：`Workflow`
- 管理账号：`UsersRound`
- 查看数据：`TrendingUp`
- 新建资源：`Plus`
- 编辑配置：`Settings`
- 更多操作：`MoreHorizontal`

图标按钮必须包含 `title` 和 `aria-label`。

### 身份账号

账号区域采用运营台式卡片：显示账号姓名、邮箱、状态、身份摘要、项目数量和工具数量。点击“查看并编辑”打开已有 `AccountDrawer`，继续在当前生态上下文中编辑基本信息、身份 Scope、项目绑定和通讯工具。启用 / 停用操作保留操作日志，并在停用时进行中文确认。

### 运营记录与风险

展示最近账号操作、待审核邀请、停用账号或权限配置异常。没有记录时显示中文空状态。风险操作使用 `AlertTriangle`、`History`、`CheckCircle`、`XCircle` 等图标，并提供清晰的中文反馈。

## 交互规则

- 新建资源继续通过角色权限过滤后的统一“新建”菜单完成。
- 所有配置类按钮打开当前页面内抽屉或弹层，不跳转独立模块。
- 对象切换时关闭当前对象详情抽屉，避免跨对象编辑。
- 成功操作使用中文 Toast；失败和空状态使用中文说明。
- 编辑、启用、停用、身份变更、项目分配、工具分配写入既有操作日志。
- 桌面端采用左树右工作区；窄屏端工作区纵向排列，抽屉保持页面内覆盖层。

## 验证标准

- 生态、SaaS、平台三种对象切换后右侧工作区上下文正确。
- 角色只能看到允许的新建资源和操作入口。
- 账号编辑、启用、停用、身份和范围配置、项目及工具分配均不跳转。
- 操作日志正常记录。
- 图标按钮有可访问性标签。
- `npm test -- --run`、`npm run build` 和 `git diff --check` 通过。
