# 会员资料栏经营摘要与会员分层指标恢复设计

**日期：** 2026-10-05  
**范围：** 会员数据右侧资料栏中的经营摘要、会员分层与现有已加入社群区块。  
**方案：** B：经营优先版。

## 目标

恢复资料栏中的经营摘要与会员分层信息，但只把已存在且可核验的数据作为确定结论展示。订单、活跃、累计消费和 RFM 尚未具备统一且按会员隔离的数据模型，因此不能把当前静态样例伪装为实时经营数据。

## 信息架构

资料栏顺序调整为：

1. 基础资料。
2. 经营摘要。
3. 会员分层。
4. 已加入社群。
5. 资料 Tabs（概览、订单、官方账号任务、运营记录、回访）。

经营摘要在基础资料之后，优先回答“当前会员处于怎样的服务与社群状态”。社群详情在分层之后保留，既能作为摘要的可追溯明细，也避免顶部出现重复的大段群名。

## 经营摘要

经营摘要展示四项已可核验或当前选中会员直接携带的数据：

- 已入社群：`selectedJoinedGroups.length`。
- 影响力：`selectedUser.influence`。
- 会员等级：`selectedUser.level`。
- 服务状态：从“邀请入群”任务的客观状态派生；无该任务时展示“未分配”。

摘要显示同步提示，但不虚构具体同步时刻。当前本地演示数据应标记为“本地演示数据”；未来接入同步时间后替换为真实时间。

不展示当前不能可靠推导的订单数、累计消费、最近活跃。

## 会员分层

会员分层分为两层：

- 当前经营标签：基于当前可核验信息生成的操作建议，不将其称为 RFM 结论。
- RFM 数据状态：分别显示 R（最近活跃）、F（购买频次）、M（累计消费）和 RFM 分层尚待数据接入或同步，不展示虚构数值。

当前经营标签规则：

- 已入群且影响力不低于榜单高影响力阈值：`高潜力会员`；建议优先回访与活动邀约。
- 已入群但未达到该阈值：`已服务会员`；建议持续内容触达与社群互动。
- 待入群、未分配群、无法添加或已退出：`待服务跟进`；建议优先完成对应关系任务。

该标签不是会员等级，不与“PRO会员、VIP”等等级混淆，也不是 RFM 分层。

## 数据边界

新增一个纯数据派生模块，集中导出资料栏所需的经营摘要和分层展示模型。该模块依赖当前已有的会员、服务关系和已加入社群数据；不依赖 UI 组件内部状态。

模块需要接收：

- 当前会员的 rank、level、influence。
- 当前会员服务关系中的邀请入群客观状态。
- 已加入社群数组。

模块输出：

- 四个经营摘要指标。
- 当前经营标签、建议与 RFM 数据状态。

后续订单与行为数据接入时，仅扩展此派生模块的输入和 RFM 字段，不改变资料栏组件的信息层级。

## 交互与异常状态

- 资料栏随当前选中会员实时刷新。
- 已入社群为 0 时，经营摘要显示 `0 个`；社群明细继续显示“暂未加入社群”。
- 未找到邀请入群任务时，服务状态显示 `未分配`。
- RFM 各字段暂以“待接入”或“待同步”表达真实数据状态，不显示占位金额、频次或客户等级。

## 验收标准

1. 经营摘要与会员分层不再被 `hidden` 永久隐藏。
2. 摘要中的社群数与社群明细数量一致。
3. 切换已入群和待入群会员时，服务状态、社群数与经营标签同步变化。
4. 页面中不再出现静态的 `3 单`、`¥1,240`、`冠军客户`、`今天` 作为资料栏经营指标。
5. 会员等级与经营标签有明确且不同的命名和位置。
6. 新增派生逻辑有独立单元测试；原有测试、生产构建和页面交互验收均通过。
