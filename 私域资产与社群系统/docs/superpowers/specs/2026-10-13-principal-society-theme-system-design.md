## 一、总体设计原则

### 1.1 主题系统定位

主理人公社小程序的主题系统**只改变视觉，不改变业务**。具体而言：

- **不改变**：页面结构、信息架构、身份权限、交互逻辑、业务文案；
- **只改变**：色板、字重强调色、卡片背景、边框颜色、阴影、按钮扫光色、hero 渐变、动态背景流光色。

### 1.2 主题分组

8 套主题分为两组：

| 分组 | 主题数 | 底色特征 | 设计语言 |
|---|---|---|---|
| 浅色潮流组 | 4 | 彩色浅底 + 白卡 | 时尚消费品感、生态陪伴感、高级工作台感、年轻化感 |
| 白底黑灰亮色组 | 4 | 纯白底 + 黑灰 + 单色亮点 | 街头潮、专业锐利、活力、平衡 |

两组共享同一套 CSS 变量，区别在于：白底黑灰亮色组额外引入 `--accent` 变量，hero、tag、price、progress 等关键部位改用 `--accent` 替代 `--brand`，确保黑灰底上的亮色只做点缀、不淹没文字。

### 1.3 动态交互策略

所有主题共用同一套动态交互层：

| 交互 | 说明 |
|---|---|
| 背景流光漂移 | body 伪元素，16s 循环，主题切换时 `--brand` / `--warning` 变化即同步换色 |
| hero 扫光 | 4.8s 循环，彩色主题用半透明白，黑白对比主题用半透明 `--accent` |
| 按钮扫光 | hover 触发，.72s 单次，白色高光沿按钮扫过 |
| 底部导航选中胶囊 | `::before` 伪元素，opacity + scale 过渡 |
| 页面切换错峰进入 | 4 条以上卡片 / 会话 / 行依次 40ms 延迟 pop in |
| 卡片悬浮微抬 | hover 时 translateY(-2px) + 边框染上 34% 主色 |
| 手机框视差 | 桌面端 pointermove 触发，perspective + rotateX/Y |
| prefers-reduced-motion | 全局 0.01ms 降级，保留功能、降低动态 |

## 二、浅色潮流组（4 套）

## 三、白底黑灰亮色组（4 套）

### 共同结构

白底黑灰亮色组共享以下基础变量：

| 变量 | 所有四套共同值 |
|---|---|
| `--page` | `#ffffff` 纯白 |
| `--surface` | `#fafafa` 近白 |
| `--surface-2` | `#f4f4f4` 浅灰 |
| `--border` | `#e5e5e5` / `#e5e7eb` 浅灰边框 |
| `--text` | `#171717` 近黑 |
| `--subtle` | `#737373` / `#6b7280` 中性灰 |
| `--shadow` | `0 18px 46px rgba(0, 0, 0, .08)` 弱阴影 |

每组唯一的差异：

| 主题 | `--brand` | `--brand-strong` | `--accent` | hero 特殊处理 |
|---|---|---|---|---|
| 墨黑荧光绿 | `#171717` | `#0a0a0a` | `#4ade80` | 白底 + 荧光绿强 |
| 石墨电蓝 | `#171717` | `#0a0a0a` | `#0a84ff` | 白底 + 电蓝 |
| 墨黑柠檬黄 | `#171717` | `#0a0a0a` | `#fde047` | 白底 + 柠檬黄 |
| 深灰荧光橙 | `#262626` | `#171717` | `#fb923c` | 白底 + 荧光橙 |

### hero、tag、price、progress 的特殊处理

白底黑灰亮色组下：

| 元素 | 彩色主题行为 | 黑白对比主题行为 |
|---|---|---|
| `.hero` | 渐变背景 + 白色文字 | 白底 + 1px 灰边 + 黑灰文字 + 亮色数字 |
| `.hero strong` | 白色 | `--accent` 亮色 |
| `.hero::after` | 半透明白色扫光 | 半透明 `--accent` 扫光 |
| `.tag` | `--brand` 背景 + 白色字 | 白底 + 灰边 + `--accent` 字 |
| `.price` | `--brand` | `--accent` |
| `.progress i` | `--brand` | `--accent` |
| `.eyebrow` | `--brand` 背景 + 白色字 | 白底 + 灰边 + `--accent` 字 |
| `.btn` | `--brand` 背景 + 白色字 | `--brand` 背景（近黑灰）+ `--accent` 字 |
| `.bottom-nav button.active` | `--brand` 文字 | `--accent` 文字 |
| `body::before / ::after` | 彩色柔光 | 关闭流光，保持纯白底干净 |

### 3.1 墨黑荧光绿（mono-lime）

## 四、主题切换机制

### 4.1 存储键

```
principal-society-preview-theme
```

### 4.2 合法值

```
peach | orchid | amber | rose | mono-lime | mono-electric | mono-lemon | mono-orange
```

### 4.3 启动逻辑

```
用户首次访问 → 无 localStorage → 默认 peach
已有 localStorage → 在合法列表内则恢复 → 不在则回退 peach
切换主题 → 写入 localStorage → body[data-theme] 同步 → CSS 变量整体换色
```

### 4.4 切换过渡

主题切换使用 CSS `transition: background .28s ease, color .28s ease`，所有引用 CSS 变量的属性（背景、文字、边框、阴影、按钮、tag）统一跟随过渡，不需要在每条规则上单独写 transition。

## 六、验收标准

主题系统验收必须全部满足：

1. 主题切换条包含 8 个按钮，文案与本文件一致；
2. 每个主题切换后 `body[data-theme]` 与 localStorage 同步更新；
3. 所有主题保持浅色底（白底黑灰亮色组为纯白底，非深色模式）；
4. 黑白对比主题下 hero 为白底带灰边，非渐变；
5. 控制台 0 错误，375 / 390px 视口下无横向滚动；
6. `prefers-reduced-motion: reduce` 下动态交互全部降级为静态；
7. 所有主题保留完整五导航：消息｜项目｜主理台｜成长｜我的；
8. 主题切换不改变任何业务数据、页面结构、身份权限或交互逻辑。
