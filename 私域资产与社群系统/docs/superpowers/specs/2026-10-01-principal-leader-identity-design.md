# 主理人平台与团长统一身份设计

## 1. 背景与目标

当前系统同时存在 D1-D5、一级/二级/三级代理、巨星/明星/微星/新星/小星星、`agent`/`leader`、会员成长等级和后台岗位等多套身份表达，导致 PC 端与主理人公社小程序端名称不一致，也容易把平台身份、业务能力和展示标签混为一体。

本次设计统一业务身份边界：

- PC 端和主理人公社小程序端统一使用 D1-D5 主理人平台身份名称。
- 团长是独立于 D1-D5 的业务身份，不是 D6，也不是主理人平台等级的下一级。
- D2-D5 可以发展或招募团长；D1 默认不直接发展团长。
- 团长负责发展社群和会员，并只运营自己负责的直属社群与会员。
- 后台岗位身份、会员成长等级和数据可见范围继续独立，不与业务身份合并。

## 2. 统一身份模型

### 2.1 平台业务身份

| 编码 | 名称 | 定位 | 是否可发展团长 |
|---|---|---|---:|
| D1 | 创始人 | 平台战略、规则与治理 | 否，默认不直接发展 |
| D2 | 核心合伙人 | 核心业务协同与团长网络发展 | 是 |
| D3 | 事业合伙人 | 事业单元经营与团长发展 | 是 |
| D4 | 分公司负责人 | 代理业务、团长招募、库存与履约 | 是 |
| D5 | 分公司合伙人 | 授权范围内的团长协作与推广 | 是 |

D1-D5 是不可被运营页面改名、增删或重排的平台预置身份。D1-D3 仍归类为公司角色，D4-D5 仍归类为代理角色。

### 2.2 独立业务身份

| 编码 | 名称 | 定位 |
|---|---|---|
| LEADER | 团长 | 发展社群与会员，负责推广、成交服务和社群运营 |
| MEMBER | 会员 | 参与社群、消费、推荐和会员成长 |

团长不属于 D1-D5 的层级树，不显示 D1-D5 编码，不使用“一级代理、二级代理、三级代理”作为身份等级，也不使用“巨星、明星、微星、新星、小星星”作为主理人平台身份。

### 2.3 非业务身份维度

以下维度保持独立：

- 后台岗位身份：平台管理员、项目运营、客服、老师等，用于后台权限控制。
- 工作台视角：`agent`、`leader` 仅表示当前工作台能力与页面视角，不代表平台等级。
- 会员成长等级：LV1-LV5 或现有会员成长配置，仅表示会员成长，不代表 D1-D5 或团长身份。
- 展示标签：可用于运营或视觉分组，但不得替代正式业务身份。

## 3. 发展与归属关系

### 3.1 团长发展规则

```text
D2 / D3 / D4 / D5
        │
        └── 发展或招募
              ↓
            LEADER 团长
              │
              ├── 发展社群
              └── 发展会员
```

- D1 默认不能直接发展团长。
- D2-D5 均具备发展或招募团长的业务能力，具体审核方式和名额由运营参数控制。
- 发展团长不等于取得团长的库存、订单、社群成员明细或日常运营权限。
- 团长必须有一个直属归属代理或业务归属范围；发展关系和直属归属关系分开记录。
- 团长成交订单继续按现有规则路由至直属代理库存，由代理负责履约、发货和售后。

### 3.2 关系字段

团长或团长申请记录至少支持以下字段：

```ts
type LeaderDevelopmentRelation = {
  leaderId: string;
  developedByIdentityId: string;
  developedByRoleCode: "D2" | "D3" | "D4" | "D5";
  directAgentId?: string;
  status: "pending" | "active" | "rejected" | "disabled";
};
```

现有网络范围模型继续区分：

- `direct_ownership`：直属归属，可管理或运营。
- `development`：发展关系，只读查看组织或聚合数据。
- `recommendation`：推荐关系，只读查看授权聚合。
- `operation`：直接运营关系，可运营直属社群和会员。

## 4. 能力边界

### 4.1 D2-D5 主理人/代理侧

D2-D5 在各自适用范围内可以：

- 发展或招募团长；
- 查看直属团长的基础资料、状态和经营聚合；
- 为团长下发推广素材、活动或培训任务；
- 查看授权范围内的团长、社群和成交聚合。

D4-D5 继续承担代理专属能力：

- 库存与进货；
- 订单履约、发货、物流和售后；
- 团长订单路由与佣金结算协作。

D2-D5 不因发展团长自动获得其直属社群和会员明细的运营权限；直属运营权限仍由关系和数据范围决定。

### 4.2 团长侧

团长可以：

- 发展并运营自己的社群；
- 发展和服务社群会员；
- 发布推广内容、领取推广素材；
- 跟进会员和意向成员；
- 推广商品并提供成交服务；
- 查看本人订单路由状态、预计佣金和结算状态。

团长不可以：

- 管理代理库存、采购、发货、物流和售后；
- 审核或管理其他团长；
- 查看非本人直属社群和会员明细；
- 将推荐关系当作直属运营或履约权限。

## 5. 小程序展示规则

### 5.1 正式身份标签

所有主理人身份标签统一显示：

- `D1 · 创始人`
- `D2 · 核心合伙人`
- `D3 · 事业合伙人`
- `D4 · 分公司负责人`
- `D5 · 分公司合伙人`

团长统一显示：

- `团长`

会员显示会员身份或会员成长等级，但不显示为 D1-D5 或团长。

### 5.2 旧名称处理

以下名称不得继续作为主理人平台正式身份展示：

- 巨星、明星、微星、新星、小星星；
- 一级代理、二级代理、三级代理。

如果历史数据仍包含这些值，应在读取或迁移时映射为正式身份、团长身份或会员成长标签；无法可靠映射的数据显示为“历史等级”，不得伪装成当前 D1-D5 身份。

### 5.3 页面范围

本次需要统一检查并修改：

- 团队总览；
- 团队等级筛选与成员列表；
- 成员详情；
- 推荐人页面；
- 团长/代理工作台身份卡片；
- 影响力排行及关系标签；
- 主理人公社小程序嵌入预览。

`agent` / `leader` 可继续用于控制工作台能力分支，但页面正式身份必须从统一业务身份字段读取，不能仅通过视角推断。

## 6. 配置设计

在现有 `levelConfig.ts` 的 D1-D5 配置基础上补充独立团长身份和团长发展能力：

```ts
type BusinessIdentityCode = PlatformRoleCode | "LEADER" | "MEMBER";

type LeaderDevelopmentRule = {
  sourceRoleCodes: Array<"D2" | "D3" | "D4" | "D5">;
  targetIdentityCode: "LEADER";
  approvalMode: ApprovalMode;
};
```

D1 的 `recruitableRoleCodes` 不新增团长；D2-D5 通过独立的团长发展规则表达，不把团长塞进 D1-D5 的等级树或 `PlatformRoleCode` 联合类型。

## 7. 验收标准

- PC 端和小程序端对 D1-D5 使用完全一致的编码和中文名称。
- 团长在所有正式身份展示中显示为“团长”，不显示为 D6、代理等级或团队视觉等级。
- 小程序不再把“巨星、明星、微星、新星、小星星”作为主理人平台等级展示。
- 小程序不再把“一级代理、二级代理、三级代理”作为主理人平台等级展示。
- D2、D3、D4、D5 的配置明确允许发展团长。
- D1 默认不能直接发展团长。
- 团长可以发展社群和会员，并只能运营授权的直属范围。
- 发展关系、直属归属、推荐关系和运营关系在数据和页面标签上明确区分。
- 团长不能访问代理库存、履约、发货、售后和团长审核能力。
- 现有会员成长等级、后台岗位权限和头像展示不被误改为平台业务身份。
- 相关工具函数、配置和页面测试覆盖 D1-D5、团长、旧等级停用和发展权限规则。
