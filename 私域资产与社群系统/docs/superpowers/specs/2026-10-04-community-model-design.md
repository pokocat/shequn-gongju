# 社群 Scope 隔离与平台级社群模型设计规范

## 背景

当前 PC 端已将社群能力收进项目配置，并完成第一轮 `CommunityScope` 迁移。但规则、群库、账号分配和群状态仍有边缘行为：未配置项目可能读取全局 fallback，多数 OPC 项目错误共享默认规则，平台级社群缺少正式入口，群编辑与归档只保存在组件内存，旧演示群会污染真实项目上下文。

本规范用于完成平台级与项目级社群的统一模型，保证切换平台或项目时，规则、群库、成员、微信账号和群状态都严格处于同一 Scope 内。

## 目标

- 以 `platform` 和 `project` 构成社群数据隔离边界。
- 平台级社群在平台工作台可进入，并使用独立平台 Scope。
- 项目未配置规则时显示明确空状态，不自动继承其他项目或全局 fallback。
- `V001 军师` 使用 AI 军师规则；其他尚未配置的 OPC 项目初始为空规则。
- 删除与当前真实 OPC 项目无关的旧演示群，避免污染真实群库。
- 平台级和项目级微信账号按明确 Scope 规则分配。
- 群编辑、归档和编号序列进入共享 Store，刷新后保持。
- 保持现有项目配置内的社群入口和视图切换体验，不恢复账号资产中心的独立社群主入口。

## 非目标

- 不重建后端接口或接入真实微信 API。
- 不改造个人微信页面的最终版结构。
- 不重做项目、平台和账号资产中心的整体信息架构。
- 不把平台级社群能力全部塞入 `PlatformModeConfig.tsx`。
- 不把模板库规则自动写入当前项目 Scope。

## 核心模型

### Scope 类型

```ts
export type CommunityScope = "platform" | "project";
```

Scope Key 统一由以下规则生成：

```text
platform:<平台名称>
project:<平台名称>:<项目名称>
```

例如：

```text
platform:主理人公社
project:主理人公社:V001 军师
```

项目 Scope 必须有非空项目名称；平台 Scope 不允许携带项目名称。所有读写接口都必须通过 Scope Key 定位数据，禁止用项目名单独作为隔离依据。

### 受 Scope 管理的数据

以下数据必须使用同一 Scope：

- 群类型规则；
- 群编号规则与序列；
- 群库；
- 群成员和入群名单；
- 成员身份与入群条件；
- 群分配规则；
- 微信账号与服务官分配；
- 群归档状态；
- 群编辑后的基础信息；
- 最近分配记录。

任何页面切换平台或项目时，必须重新计算 Scope Key，并以该 Key 读取完整数据，不允许从上一个 Scope 回退读取。

## 平台级社群入口

平台级社群入口放在生态管理的“平台工作台”内，而不是账号资产中心，也不放入仅管理平台模式、角色、版本和权限的 `PlatformModeConfig`。

平台工作台提供独立的社群配置区，至少包含：

- 平台概览；
- 平台群类型规则；
- 平台社群；
- 平台可见性与权限入口。

进入“平台社群”后使用：

```text
platform:主理人公社
```

平台级创建群时不携带项目字段；平台级群库只展示平台 Scope 的群。项目级入口继续位于对应项目配置抽屉的“项目社群”中。

## 规则来源与初始化

### 生效规则

当前 Scope 的生效规则只来自 `rulesByScope[scopeKey]`。不存在该 Key 或规则数组为空时，页面显示“尚未配置群类型规则”，创建社群按钮不可提交。

`defaultGroupTypeRules` 和 `FALLBACK_RULES` 不再作为未知项目或空项目的隐式生效规则。模板规则只能在用户明确选择“套用模板”后复制到目标 Scope，再由用户保存。

### 初始项目规则

项目初始数据按以下规则配置：

- `V001 军师` 使用 `AI_STRATEGIST`；
- `AI超级广告公司`、`AI艺人孵化`、`AI数字资产平台`、`AI大健康`、`AI知识付费`、`AI教育`、`AI明星艺人授权`、`AI企业礼品采购` 初始为空数组；
- 平台级规则单独初始化，不从任一项目规则复制；
- 已存在的 Scope 数据优先于初始数据，避免刷新或迁移时覆盖用户保存的规则。

模板浏览和模板套用必须与当前生效规则区分显示。套用动作需要明确目标 Scope，并执行规则深拷贝。

## 微信账号分配

微信账号模型增加明确的归属范围，采用平台公共池与项目专属池并存的方式：

- 平台公共账号可服务平台级群，也可在明确允许时服务项目级群；
- 项目专属账号只服务对应项目 Scope；
- 项目账号不得被其他项目复用；
- 平台级创建群优先选择平台公共池；没有可用账号时显示“待分配”，不得静默使用其他项目账号；
- 项目级创建群优先选择该项目专属池，必要时再使用平台公共池；
- 账号选择同时校验城市、启用状态和群容量。

现有旧账号演示数据只在归属明确时保留；无法映射到真实平台或项目 Scope 的账号不参与当前社群创建分配。

## 群库与演示数据

当前 `SEED_GROUPS` 中的“体验官”“PRO会员”“城市分站”不属于现有 OPC 项目，且部分微信账号不存在于当前账号池。为避免真实数据污染，本轮删除这些旧演示群，不再注入真实项目群库。

后续若需要演示数据，必须使用独立演示 Scope，且不能与 `主理人公社` 的平台或 OPC 项目 Scope 相同。真实群库只由已迁移的 Store 数据和用户创建的群组成。

## Store 持久化模型

`communityDataStore.ts` 继续作为社群共享状态唯一入口。除 `rulesByScope` 和 `generatedGroups` 外，增加以下 Scope 维度状态：

```ts
groupEditsByScope: Record<string, Record<string, Partial<SharedGroup>>>;
archivedGroupNosByScope: Record<string, string[]>;
groupSequencesByScope: Record<string, number>;
```

`SharedGroup` 的 `platform`、`scope` 必须存在；项目 Scope 的 `project` 必须存在，平台 Scope 的 `project` 必须为空。旧 localStorage 数据加载时完成兼容迁移，并为无法确认归属的旧群跳过真实 Scope 注入。

群编辑和归档必须通过 Store API 读写，组件只保留当前交互状态，例如当前打开的编辑弹窗和当前选中的群。刷新页面后，群列表、编辑结果和归档结果保持一致。

更新群信息时，Store API 必须接收目标 Scope，并校验群的 Scope 与目标 Scope 一致。Scope 不一致时拒绝更新，避免同编号群被错误修改。

## 群编号策略

群编号和群运营编号均在 Scope 内生成：

- 每个 Scope 拥有独立递增序列；
- 序列只增不减，归档群不会释放编号；
- 生成前校验当前 Scope 内的群编号和群运营编号唯一；
- 平台 Scope 与项目 Scope 不共享序列；
- 从旧数据迁移时，序列从当前 Scope 最大编号继续。

群编号的展示格式继续复用现有规则编码、地区编码和序号逻辑，但序号来源改为 Store 的 Scope 序列，不再使用当前群列表长度。

## 组件职责

### `EcosystemManagement.tsx`

负责平台工作台和项目配置的入口、Scope 初始化、规则保存，以及平台级社群入口。平台入口和项目入口都传入完整的 `platform`、`scope`、`project` 上下文。

### `ProjectCommunitySystem.tsx`

负责当前 Scope 下的群库、创建群、编辑群、归档群、成员名单和分配规则展示。组件不读取全局 fallback，不自行持久化业务状态，不拼接其他 Scope 的数据。

### `communityDataStore.ts`

负责 Scope Key、规则、群库、编辑、归档和编号序列的统一读写、迁移和持久化，并提供带 Scope 校验的 API。

### `projectGroupRules.ts`

负责规则模板、规则映射、地区编码和账号池选择策略。未知项目只返回空数组或明确的模板列表，不返回默认生效规则。

### `WeChatManagement.tsx`

当前项目规则展示优先读取当前平台和项目 Scope 的生效规则；模板统计继续使用模板数据，但必须标识为模板，不得冒充当前项目已启用规则。

## 错误与空状态

- 当前 Scope 无规则：显示“尚未配置群类型规则”，引导进入群类型规则配置；
- 当前 Scope 无群库：显示“该 Scope 暂无社群”，不显示其他项目群；
- 无可用微信账号：允许创建但标记“待分配”，并给出账号配置提示；
- Scope 参数不完整：阻止创建和保存，显示上下文配置错误；
- 发现旧数据无法归属：不展示在真实 Scope，并保留迁移告警信息；
- 发现重复编号：拒绝写入并重新申请 Scope 序列。

## 验证标准

### 数据隔离

- 进入平台级社群时只看到 `platform:主理人公社` 数据；
- 进入 `V001 军师` 时只看到 `project:主理人公社:V001 军师` 数据；
- 切换到 `AI超级广告公司` 后不显示 `V001 军师` 的规则、群库、成员或微信绑定；
- 未配置 OPC 项目显示空状态，不显示 AI 学习社群或其他模板的生效规则。

### 创建与持久化

- 平台级创建群写入平台 Scope，不带项目字段；
- 项目级创建群写入对应项目 Scope，带正确项目字段；
- 群编号在 Scope 内唯一，归档后不会复用；
- 编辑群信息后刷新页面，修改仍存在；
- 归档群后刷新页面，群仍不出现在群库；
- Scope 不匹配的更新请求不会修改群数据。

### UI 与工程验证

- 平台工作台能进入平台级规则和平台社群；
- 项目配置仍能进入项目规则和项目社群；
- 视图选择器下拉菜单保持完整显示；
- `npm run build` 通过；
- `npm test -- --run` 通过；
- `git diff --check` 通过；
- 使用真实浏览器验证平台、V001 和其他 OPC 项目之间的 Scope 切换。

## 迁移与兼容

- 继续读取旧 `rulesByProject`，迁移为默认平台下的项目 Scope；
- 对旧群补全平台和 Scope 时，仅保留可以确认归属的数据；
- 清理与当前 OPC 项目无关的旧种子群，不将其迁入任何真实项目；
- 保留旧项目规则 API 作为兼容层，但内部统一调用 Scope API；
- localStorage 版本保持可读取，新增字段缺失时使用空对象、空数组和 Scope 序列初始化。
