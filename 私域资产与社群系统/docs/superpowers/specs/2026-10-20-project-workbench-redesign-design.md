# 项目工作台页面重构设计规格

## 状态

待用户审阅；本规格获批前不进入实现。

## 背景与问题

当前“项目与商城”页同时展示项目、社群推荐和商城，但主次不清。商城区域通过负向位移强行上移，存在模块重叠风险。项目详情页只介绍内容与权益，缺少用户参与状态、进度以及明确的下一步操作。

## 目标

将页面重构为“我的项目优先”的项目工作台，让用户打开页面即可识别正在参与的项目、当前进度和下一步行动；同时保留发现并进入其他项目、浏览社群资源和商城的能力。

## 非目标

- 不改动消息页、私聊页或群聊能力。
- 不新建后端接口、报名支付流程或项目管理数据系统。
- 不改变现有 TabBar、应用导航协议及项目页面路由。
- 不扩展为完整项目管理或任务管理系统。

## 信息架构与视觉层级

主页采用以下顺序：

1. **工作台标题区**：说明页面是项目工作台，精简现有泛化宣传文案；必要的精选/项目总数信息作为次级信息，不与主任务竞争。
2. **正在进行**：首屏主视觉项目卡。突出项目名称、参与状态、项目周期与进度、下一步任务，并提供明确的“继续项目”入口。视觉沿用现有品牌紫色渐变和主题 token，不引入新的视觉体系。
3. **适合你报名 / 发现项目**：展示尚未参与、当前可进入的项目卡片，包含项目名称、简要价值、状态或名额信息以及“查看详情/报名”入口。未实现真实报名服务时，不暗示报名已经成功。
4. **社群资源与商城**：作为次级入口展示，视觉弱于项目卡片。商城恢复正常文档流，删除负向位移布局。

项目内容较多时按内容自然纵向滚动，不通过重叠、绝对定位或负 margin 压缩模块。

## 项目状态与详情页

### 主理人成长营

- 对已参与用户显示“进行中”状态、周期进度（视觉草案示例为第 8/21 天）及下一步任务（示例为完成本周经营复盘）。这些均为展示用示例，接入实现时应优先复用项目中已有数据；若没有可用数据，不伪造动态进度，改为显示清晰的项目阶段/内容摘要。
- 详情页分区呈现项目简介、参与状态/进度、下一步行动、项目内容与权益。
- 主操作“继续项目”指向当前可用的项目内容/学习入口；只有存在真实报名能力时才显示报名操作。

### 私域选品共学营

- 作为可发现项目展示，保留已有的每周选品、测试、复盘和共学信息。
- 详情页明确标示可参与/报名状态（以现有可确认的信息为准），提供清晰主操作；无报名实现时只进入项目详情，不出现虚假成功反馈。
- 详情页分区呈现项目简介、参与方式/开放信息、项目内容与权益。

两个详情页均保留返回项目工作台入口，并维持现有 `data-nav` / 页面路由约定及 iframe 嵌入场景导航行为。

## 数据与交互约束

- 先检查仓库中可复用的项目、报名、进度、任务数据；不新增虚构的数据源。
- 若当前页面没有当前用户的真实参与状态或任务数据，采用明确的静态状态文案，不将演示数字表述为真实用户状态。
- 主页项目卡、详情入口、社群推荐、商城与返回入口均保持可点击，并正确保留现有查询参数及嵌入导航行为。
- 继续沿用项目既有 CSS 变量、字号、卡片圆角与移动端布局规范。

## 验收标准

1. 主页第一视觉焦点是进行中项目及其下一步行动，而不是社群推荐或商城。
2. 主页顺序清楚地区分进行中项目、可发现项目和辅助资源入口。
3. 商城模块不再使用负向位移或负 margin，不与相邻模块重叠。
4. 成长营和选品共学营详情页均能让用户识别项目状态、项目内容/权益与下一步入口；没有真实动态数据时不展示伪造进度。
5. 现有两个项目入口、商城入口、社群入口和返回入口可正常导航；独立页面及 iframe 嵌入场景均可工作。
6. 窄屏纵向浏览无横向溢出、卡片遮挡或被 TabBar 覆盖的主要操作。
7. 相关测试通过，项目构建成功，并完成主页及两个详情页的浏览器视觉检查。

## 待确认的设计判断

- “我的项目优先”为已选方向。
- 进度和下一步任务的示例内容只用于视觉表达；实现阶段须以仓库现有数据为准，否则使用不误导用户的静态内容。
- 报名能力不在本次范围内；入口仅在已有真实能力时开放报名动作。
