# 主理人公社双端统一小程序重设计

## 1. 背景与目标

基于最近的主理人公社移动端需求、现有主理人小程序能力，以及 PC 端社群管理工具的信息架构和视觉语言，重新设计一套面向主理人本人的双端统一产品。

产品同时服务于 H5 移动端和原生微信小程序。两端共用业务模型、页面结构、交互语义、状态文案和主题系统；允许根据平台能力采用不同的页面容器、授权流程、通知方式和系统控件表现。

首期目标是让主理人打开产品后快速完成三件事：

1. 识别今天最重要的待处理事项；
2. 处理需要关注的社群、成员和项目节点；
3. 通过成长值、课程和权益获得持续反馈。

本项目不是将 PC 页面缩小，而是以“今日行动”为移动端首屏核心，保留 PC 端社群与项目管理能力，并把复杂管理动作拆分为适合移动端连续处理的流程。

## 2. 范围与非目标

### 2.1 首期范围

- 主理人工作台
- 社群列表、社群详情和状态筛选
- 项目列表、项目详情和下一步动作
- 成员跟进相关的行动项
- 成长等级、成长任务、课程和权益入口
- 个人资料、通知、账号设置和主题设置
- H5 与微信小程序的统一设计规则
- 三套可切换 UI 主题
- 加载、空状态、错误、无权限、成功反馈等通用状态

### 2.2 首期不做

- 完整聊天系统
- 复杂 CRM 自动化
- 多角色权限管理后台
- 超级管理员生态配置
- 高级报表和数据分析
- 复杂课程内容编辑器
- 社群自动化运营规则
- 多组织、多租户配置
- 自定义主题编辑器

## 3. 产品组织方式

采用“行动工作台型”组织方式，融合资产管理和消息提醒能力。

核心原则：

> 首页帮助主理人行动，二级页面帮助主理人管理，个人中心帮助主理人成长和配置。

底部导航固定为：

- 工作台
- 社群
- 项目
- 成长
- 我的

工作台为默认首页。首页优先级为：

```text
今日行动 > 社群关注 > 项目进展 > 快捷操作 > 成长反馈
```

## 4. 信息架构

### 4.1 工作台

工作台顶部显示问候语、主理人头像、当前身份或等级、通知入口和主题快捷入口。

主体区域包括：

- 今日行动：最多展示 3 条最重要事项
- 我的社群：最多展示 2 个重点社群
- 项目进展：最多展示 2 个重点项目
- 快捷操作：新建任务、添加成员、创建项目记录、发布社群通知、查看全部消息
- 成长进度：等级、成长值、已完成任务和可领取权益

点击行动项直接进入对应处理页面。完成后返回工作台并刷新聚合状态。当天无待办时展示明确的积极空状态。网络异常时保留最近一次缓存并显示更新时间。

### 4.2 社群

社群列表以移动端卡片呈现，不复制 PC 表格。卡片显示社群名称、类型、状态、人数与容量、活跃度、今日新增、待跟进事项和更新时间。

支持筛选：

- 全部
- 活跃中
- 需要关注
- 已归档

社群详情分为：

- 概览：人数、活跃度、新增成员、待跟进事项
- 成员：成员列表、标签、最近互动、项目关系
- 动态：社群事件、公告、运营记录
- 设置：社群信息、权限、关联项目、归档操作

需要关注状态必须显示具体原因，原因包括待跟进成员、活跃度下降、容量接近上限或重要通知未处理。

### 4.3 项目

项目列表显示项目名称、类型、阶段、负责人、关联社群、下一步动作和状态。状态统一为：未开始、进行中、待确认、已完成、已暂停。

项目详情包括：

- 项目概览
- 里程碑
- 关联成员
- 关联社群
- 合作方
- 跟进记录
- 文件或资料入口

移动端优先展示当前阶段、下一步动作、责任人、截止时间和最近进展。

### 4.4 成长

成长页面包括成长等级、成长进度、待完成成长任务、推荐课程、已获得权益、可领取权益和成长记录。

成长模块服务于持续参与，不设计成复杂商城。基本闭环为：完成任务、获得成长值、解锁权益、继续行动。

### 4.5 我的

我的页面包括主理人资料、标签、账号、通知设置、UI 风格设置、数据同步状态、帮助与反馈和关于主理人公社。

## 5. 视觉主题系统

主题采用“语义变量 + 主题配置”。页面和组件只使用语义变量，不直接绑定具体颜色。主题只改变视觉表现，不改变页面结构、数据字段、权限逻辑和操作流程。

### 5.1 社群蓝：专业协同型

### 5.4 主题可配置变量

基础变量包括品牌色、页面背景、卡片背景、主文本、次文本、弱文本、边框、成功、警告、错误、信息、导航选中态、进度和焦点色。

组件变量包括卡片圆角、按钮圆角、标签圆角、卡片阴影、弹层阴影、页面间距、区块间距、卡片间距、内容密度、标签样式、导航选中态和进度条样式。

主题可在“我的 → UI 风格”中切换，也可以从工作台右上角快捷进入。切换后立即应用，保存到本地；登录后同步账户设置。同步失败时保留本地生效状态并提示结果。H5 和微信小程序使用相同主题名称和语义变量。

## 7. 数据流与状态处理

工作台聚合 ActionItem、成员跟进、社群关注、项目里程碑、通知和成长任务。详情页变更业务数据后，返回工作台时刷新对应聚合；不允许详情页和工作台维护互相独立的同一状态。

所有核心页面统一覆盖：

- 加载中：使用骨架屏，保持布局稳定
- 空状态：说明当前状态并提供明确下一步按钮
- 错误状态：显示原因、重试、最近更新时间，并尽量保留缓存
- 无权限：说明账号暂时无权访问，并提供返回工作台和联系管理员入口
- 成功反馈：使用 Toast、顶部提示或按钮状态变化，避免不必要的阻塞弹窗

## 8. 双端适配规则

### 8.1 统一内容

H5 与微信小程序保持一致的页面名称、导航顺序、卡片信息层级、状态文案、操作结果、错误提示、主题名称和账号同步规则。

### 8.2 H5

H5 以移动端单列为默认，宽屏下使用舒适内容限宽。支持手势返回、下拉刷新、Toast、底部抽屉、弹窗和长列表分页或滚动加载。PC 端可以复用同一套数据卡片，但不强行复用移动端底部导航。

### 8.3 微信小程序

微信小程序遵循安全区和不同状态栏高度，底部导航避开系统手势区域。使用微信原生返回和页面栈，接入授权、登录态、订阅消息或服务通知。重要操作保留微信式确认反馈，不依赖 hover。

### 8.4 允许差异

两端允许在页面返回、授权流程、通知能力、分享能力、文件和图片选择方式，以及输入框和弹窗的原生表现上存在平台差异，但不得改变业务含义和关键路径。

## 9. 首期关键路径

```text
打开小程序
  -> 查看今日行动
  -> 点击待跟进成员
  -> 查看成员信息与最近互动
  -> 完成跟进记录
  -> 返回工作台
  -> 查看需要关注的社群
  -> 进入社群详情
  -> 处理社群异常或查看动态
  -> 查看项目下一节点
  -> 完成或更新项目进展
  -> 获得成长值或权益反馈
```

验收重点是“工作台 → 行动项 → 详情 → 完成操作 → 返回工作台”在 H5 和微信小程序均可完成。

## 10. 首期验收标准

### 工作台

- 默认进入工作台
- 能看到今日待处理事项
- 今日行动最多展示 3 条重点内容
- 点击行动项可进入对应详情
- 完成行动项后状态实时更新
- 无数据时有明确空状态
- 网络异常时保留缓存并显示更新时间
- 主题切换不改变布局

### 社群

- 能查看社群列表并按状态筛选
- 能区分正常、需要关注和已归档
- 卡片展示人数、活跃度和待跟进事项
- 点击卡片进入详情
- 详情能查看成员、动态和关联项目

### 项目

- 能查看项目列表
- 能识别项目状态和进度
- 能看到下一步动作和截止时间
- 能进入项目详情并查看关联社群和成员
- 更新项目进度后，工作台对应内容同步变化

### 成长

- 能看到等级和成长值
- 能查看成长任务
- 真实业务行为完成后能看到成长反馈
- 能查看已获得或待领取权益
- 成长内容不遮挡今日行动

### 主题

- 默认使用社群蓝
- 可以切换主理人绿和主理人黑
- 切换后当前页面立即更新
- 刷新后主题保持
- 登录后主题可同步
- 两端主题名称和颜色语义一致
- 三套主题均保持可读性和状态识别

### 双端

- 同一账号在两端看到一致的核心数据
- 一端完成任务后，另一端刷新可看到最新状态
- 主题偏好按产品规则保持同步
- 两端均可完成主关键路径

## 11. 风险与边界

首期主题只支持预设主题选择，不开放自定义配色，避免产生不可控的对比度和品牌组合。数据聚合必须以业务详情数据为来源，避免工作台出现过期副本。移动端只暴露主理人完成高频行动所需的信息，复杂配置保留给 PC 端或后续阶段。

实现阶段应优先复用现有主理人移动端的页面编排、消息详情、成长详情、账户详情、真实头像资源和已有交互能力，避免重复建设；除必要文件外不修改无关模块，不引入未经确认的新依赖。
