# 项目级关系任务工作模式设计规范

## 1. 背景

总运营工作台需要同时监管两类信息：工作人员是否执行了添加好友、联系会员、邀请入群等服务动作，以及 AI 手机或外部系统核验到的真实关系结果。

两类信息不能互相替代：

- 人工点击“添加”只代表工作人员执行过一次服务动作，不代表好友已经添加成功；
- 人工点击“邀请入群”只代表工作人员执行过一次邀请动作，不代表会员已经入群；
- 个微、企业微信、入群等客观关系状态必须由 AI 手机或外部系统同步；
- 管理员需要通过客观状态与人工操作记录的差异，判断服务是否真实完成。

不同项目对工作人员的信息可见范围可能不同，因此需要支持按项目配置关系任务工作模式。每个项目内部统一使用一种模式，不允许在同一项目内对个微、企业微信、入群或官方账号任务分别设置模式。

## 2. 目标

- 为每个项目增加统一的关系任务工作模式配置。
- 支持不同项目分别选择不同模式。
- 支持监管透明模式和任务执行模式。
- 管理员、区域管理员、项目负责人可以修改项目模式。
- 工作人员不能修改项目模式，只能遵循当前项目配置。
- 模式保存后立即生效。
- 保留原有 `personal`、`enterprise`、`group`、`spend`、`ai` 关系字段。
- 保留工作人员的添加、联系、邀请入群等操作按钮。
- 将客观关系状态、人工服务记录和当前任务状态明确分离。
- 管理员始终可以查看完整客观状态、人工操作记录及两者差异。
- 模式切换不删除历史数据，不覆盖历史记录。

## 3. 非目标

本次设计不包含：

- 人工创建会员；
- 人工新增、编辑或删除会员项目和会员权益；
- 人工直接修改 AI 或外部系统同步的客观关系状态；
- 同一项目内按单个任务分别配置工作模式；
- 工作人员个人自由选择工作模式；
- 接入真实 AI 手机、企业微信或其他外部系统 API；
- 建立完整后端权限服务或持久化数据库。

当前实现阶段继续使用项目现有的本地模拟数据和 React 状态管理，但数据结构必须按照未来真实接口可替换的方式组织。

## 4. 核心业务规则

### 4.1 项目级统一配置

每个项目只有一个关系任务工作模式：

```text
项目 A → 监管透明模式
项目 B → 任务执行模式
项目 C → 监管透明模式
```

同一项目中的以下任务必须使用同一个模式：

- 服务官个微；
- 班主任企业微信；
- 官方素材微信；
- 官方公众号；
- 官方视频号；
- 官方小红书；
- 官方抖音；
- 会员服务群。

### 4.2 人工操作不等于客观成功

工作人员可以执行：

- 添加个微；
- 添加企业微信；
- 联系会员；
- 邀请入群；
- 再次引导；
- 再次跟进。

每次操作需要记录：

- 操作动作；
- 操作对象；
- 操作人员；
- 操作时间；
- 操作次数；
- 服务结果或备注。

这些记录不得直接修改 `personal`、`enterprise`、`group` 或 AI 客观状态。

### 4.3 客观状态来源

客观状态只能来自：

- AI 手机核验；
- 个微或企业微信外部系统同步；
- 社群系统同步；
- 会员、项目或其他业务小程序同步；
- 未来接入的其他可信外部系统。

客观状态变化需要记录来源、同步时间和必要的核验信息。

### 4.4 管理员完整可见

管理员、区域管理员和项目负责人始终可以查看：

- 客观关系状态；
- AI 或外部系统来源；
- 最近同步时间；
- 人工操作次数；
- 操作人员和操作时间；
- 当前任务状态；
- 人工操作与客观结果之间的异常差异。

项目模式不能限制这些管理角色的监管视图。

## 5. 工作模式

### 5.1 监管透明模式

模式标识：`transparent`

工作人员可以看到 AI 手机或外部系统同步的客观关系状态，并据此决定下一步服务动作。

工作人员视图示例：

```text
服务官个微
客观状态：未添加
人工服务：已操作 2 次
最近操作：张三 · 2026-10-03 14:20
下一步：再次联系
```

可见内容：

- 客观状态；
- 状态来源；
- 最近同步时间；
- 人工操作汇总；
- 待执行任务；
- 异常提示。

不可执行的动作：

- 直接把客观状态改为“已添加”；
- 直接把入群状态改为“已入群”；
- 直接覆盖 AI 或外部系统结果。

### 5.2 任务执行模式

模式标识：`execution`

工作人员只看到待执行任务、服务要求和人工服务记录入口，不看到 AI 或外部系统的最终客观判断。

工作人员视图示例：

```text
待添加服务官个微
服务要求：主动联系会员并完成添加引导
人工服务：已操作 1 次
下一步：提交跟进记录
```

工作人员可见：

- 任务标题；
- 服务要求；
- 执行动作按钮；
- 操作次数；
- 操作人员；
- 操作时间；
- 服务结果和备注；
- 任务处理状态。

工作人员不可见：

- AI 是否判断已添加；
- 外部系统是否判断已入群；
- 客观状态的最终值；
- 客观核验来源和差异原因。

管理角色仍然可以查看完整客观信息，不受该模式影响。

## 6. 数据模型

### 6.1 项目工作模式配置

```tsx
type ProjectRelationshipWorkMode =
  | "transparent"
  | "execution";

type ProjectWorkModeConfig = {
  projectId: string;
  mode: ProjectRelationshipWorkMode;
  updatedAt: string;
  updatedBy: string;
};
```

项目配置建议以项目 ID 为键保存：

```tsx
type ProjectWorkModeByProject = Record<
  string,
  ProjectWorkModeConfig
>;
```

没有显式配置的项目使用默认模式，默认值为 `transparent`，以保持现有工作台行为兼容。

### 6.2 人工服务操作日志

```tsx
type ManualServiceLog = {
  id: string;
  memberId: string;
  projectId: string;
  taskId: string;
  action: string;
  result: string;
  operator: string;
  at: string;
  note?: string;
};
```

`count`、`status`、`operator` 和 `at` 可以继续作为当前任务的汇总字段，但汇总字段必须由操作日志推导或同步更新，不得成为唯一记录。

### 6.3 客观关系状态日志

```tsx
type RelationshipChangeLog = {
  id: string;
  memberId: string;
  projectId?: string;
  field: "personal" | "enterprise" | "group";
  before: string;
  after: string;
  source: "external-sync" | "ai-check";
  operator?: string;
  reason?: string;
  at: string;
};
```

人工按钮不能产生伪造的客观状态变更日志。人工操作只产生 `ManualServiceLog`。

### 6.4 当前任务状态

当前任务状态用于描述服务流程，不代表客观关系结果：

```text
待执行
处理中
已操作
待再次跟进
已提交结果
已完成
异常
```

任务状态可以由人工操作推动，但必须与客观关系状态并列展示。

## 7. 配置入口与交互

### 7.1 项目档案配置入口

在项目数据的项目档案中增加“关系任务工作模式”配置区。配置区包含：

- 当前模式；
- 两种模式的名称和说明；
- 当前配置人；
- 最近更新时间；
- 保存按钮；
- 模式变更提示。

推荐文案：

```text
关系任务工作模式

监管透明模式
工作人员可以看到 AI 手机或外部系统同步的真实状态，
只针对尚未添加、尚未入群或尚未关注的对象进行后续联系。

任务执行模式
工作人员只看到待执行任务和服务要求，
看不到 AI 手机或外部系统的最终判断结果。
```

### 7.2 权限行为

- 系统管理员：可查看、修改所有项目模式；
- 区域管理员：可查看、修改授权区域内项目模式；
- 项目负责人：可查看、修改负责项目模式；
- 项目运营、社群运营、服务老师：只能查看工作台当前模式并执行任务；
- 其他无项目权限的角色：不能进入项目配置，也不能查看该项目关系任务。

当前若权限系统还没有完整的项目范围判断，前端至少要先区分“可配置角色”和“只读角色”，并保留后端权限接入点。

### 7.3 工作台模式提示

工作台当前项目上下文中显示模式徽标：

```text
当前项目：PRO会员项目 · 监管透明模式
```

工作人员只能查看提示，不能在工作台直接切换模式。

## 8. 模式切换与数据流

模式切换流程：

1. 管理员或项目负责人进入项目档案；
2. 选择新的关系任务工作模式；
3. 系统校验当前用户是否有该项目配置权限；
4. 保存项目配置；
5. 立即更新项目模式状态；
6. 当前项目的关系任务视图按新模式渲染；
7. 记录配置人、更新时间和旧值到配置变更日志。

模式切换只影响信息可见性和任务视图，不改变：

- 会员资料；
- `personal`、`enterprise`、`group`、`spend`、`ai` 原始字段；
- AI 或外部系统核验结果；
- 人工服务日志；
- 历史任务记录；
- 项目和权益同步数据。

从监管透明模式切换到任务执行模式时，只隐藏工作人员不应看到的客观结果，不删除客观结果。

从任务执行模式切换到监管透明模式时，工作人员可以立即看到当前最新客观结果，但历史期间未展示给工作人员的结果不需要补写到历史人工记录中。

## 9. 差异监管视图

管理角色在会员档案中看到三列并列信息：

```text
客观关系状态
人工服务记录
当前任务状态
```

当出现以下情况时显示异常提示：

- 人工操作次数大于 0，但客观状态仍为未添加或未入群；
- 多次人工操作后仍没有外部系统同步结果；
- 客观状态已成功，但没有任何人工操作记录；
- 任务已标记完成，但客观状态仍待核验；
- 客观状态和人工填写的服务结果不一致。

异常提示只能帮助管理员监管，不能自动把一方数据覆盖为另一方数据。

## 10. 错误与边界处理

- 未配置项目模式时，使用监管透明模式作为兼容默认值，并在项目档案提示“尚未显式配置”；
- 项目切换时，工作台必须重新读取当前项目模式，不能沿用上一个项目的模式；
- 用户无权修改模式时，配置控件为只读或不显示保存按钮；
- 保存失败时保留当前已生效模式，不显示虚假的成功提示；
- 模式切换期间不能清空或覆盖人工操作日志；
- AI 或外部系统更新失败时，保留最近一次客观状态并显示更新时间和失败提示；
- 工作人员在任务执行模式下不能通过浏览器状态、表单提交或本地交互修改客观状态；
- 管理员查看差异时，即使没有人工日志或客观同步日志，也要显示明确的空状态，而不是把缺失解释为成功；
- 同一项目只能有一个生效模式，不能出现多个任务模式同时生效。

## 11. 代码范围建议

首期实现集中在以下位置：

- `src/app/components/workbenchScopes.tsx`
  - 扩展项目配置类型或提供项目 ID 映射；
  - 为项目数据提供可识别的项目配置入口。

- `src/app/components/PCLayout.tsx`
  - 保持当前项目切换；
  - 提供当前项目上下文给工作台；
  - 不在项目切换控件中直接混入模式切换逻辑。

- `src/app/components/InfluenceRanking.tsx`
  - 读取当前项目工作模式；
  - 显示工作模式徽标；
  - 按角色和项目模式控制客观状态可见性；
  - 保留人工服务按钮；
  - 分离人工操作日志和客观状态展示；
  - 增加管理员差异视图。

- `src/app/components/MemberOperationsWorkbench.tsx`
  - 作为工作台外层承接项目和当前用户角色上下文；
  - 统一向会员关系任务传递模式信息。

- `src/app/components/Permissions.tsx`
  - 补充项目工作模式查看和配置能力的展示；
  - 保留未来接入细粒度项目权限的接口边界。

- `src/app/components/CustomerService.tsx`
  - 对齐项目负责人、项目运营、社群运营和服务老师的模式查看权限。

可新增：

```text
src/app/data/projectWorkModes.ts
```

用于集中保存项目模式类型、默认配置、模式文案和权限辅助函数，避免将模式值散落在多个组件中。

## 12. 验证标准

### 功能验证

- 项目 A 设置为监管透明模式后，工作人员能看到客观关系状态；
- 项目 B 设置为任务执行模式后，工作人员看不到 AI 或外部系统最终判断；
- 同一项目内所有关系任务统一使用项目模式；
- 切换项目时，模式和可见字段随项目变化；
- 修改模式后立即影响当前项目任务视图；
- 工作人员不能修改项目模式；
- 管理员、区域管理员、项目负责人可以修改授权项目模式；
- 工作人员点击添加、联系或邀请入群后，操作次数、人员和时间会更新；
- 人工操作不会修改 `personal`、`enterprise`、`group` 或 AI 客观状态；
- 管理员始终能看到客观状态、人工记录和差异；
- 模式切换不会删除历史人工日志和客观状态日志；
- 项目和权益仍保持外部同步只读边界。

### 回归验证

- 会员、社群、项目、代理四类经营视角仍可切换；
- 非会员视角不会显示会员专属 AI 任务；
- 统一待办仍能定位到对应会员和项目；
- 项目档案原有项目指标、任务和里程碑展示不被破坏；
- 页面无白屏、React 运行时错误或未捕获异常；
- 运行 `yarn build` 通过；
- 运行 `yarn test` 通过；
- 使用浏览器验证至少覆盖管理员视图、工作人员透明模式和工作人员任务执行模式。

## 13. 后续扩展

以下能力不纳入本次首期实现，但数据结构需要预留：

- AI 手机和外部系统的真实同步任务 ID；
- 同步失败、重试、取消和超时；
- 客观状态来源优先级；
- 置信度和核验证据；
- 项目模式变更审批；
- 配置变更历史时间线；
- 后端权限校验；
- 统一任务、工单和回访对象的持久化；
- 客观状态与人工记录的监管报表。
