# 账号资产详情统一设计规范

## 背景

账号资产中心的“全部”视图使用通用 `AccountsAndResourceCenter`，其右侧详情仍沿用旧版资源台账结构，并固定优先选中抖音资源 `dy_bj_01`。这会导致左侧混合账号列表与右侧详情对象不一致，也使底部出现过多低频操作。个人微信 `WeChatManagement` 已是确认版，本改造以其详情骨架为统一参考，不修改个人微信页面。

## 目标

- “全部”、企业微信、手机号、邮箱、媒体账号和混合资产的详情结构统一到个人微信的使用方式。
- 详情对象始终属于当前筛选结果，并与当前选中列表项一致。
- 保留各账号类型的字段和运营数据，但降低信息架构差异。
- 底部仅保留高频主操作，低频和危险操作收纳到更多操作。

## 详情结构

顶部身份区保留头像或类型图标、名称、类型、状态、唯一标识、平台或绑定信息，并保留二维码入口（仅在账号类型支持时展示）。

详情标签统一为四组：

1. 账号资料：账号标识、昵称或名称、类型、状态、认证、同步信息、备注。
2. 绑定分配：项目、归属人、部门、大区、岗位、绑定手机号或邮箱，并提供前往绑定分配的入口。
3. 运营数据：好友、粉丝、群或会话、每日上限、今日使用量，以及媒体账号的运营指标。
4. 个人安全：风险等级、最近登录、登录设备、同步异常、安全配置和操作日志摘要。

不同类型允许在四组标签内部显示差异化字段，但不再使用“通用 / 媒体·运营专属 / 风控 / 操作日志”作为顶层标签。

## 操作层级

底部固定保留两个主操作：

- 编辑：打开当前资源的编辑或资料更新入口。
- 发起交接：沿用现有交接审批流程。

其余操作进入“更多操作”菜单：

- 改项目
- 改归属人
- 同步
- 查看二维码
- 送回养号
- 停用
- 归档
- 媒体账号的加入矩阵
- 媒体账号的申请商单

危险操作继续使用现有确认弹窗和审计日志，不改变业务行为。

## 选择与筛选行为

- 删除默认优先选中 `dy_bj_01` 的逻辑。
- 首次进入或切换筛选后，若存在结果，默认选择当前筛选结果第一条。
- 当前选中项不在筛选结果中时，自动切换到筛选结果第一条；无结果时清空详情。
- 详情不得通过全量 `tools` 回退到当前筛选范围之外的资源。
- 切换账号类型、状态、生命周期、维度和高级筛选时，保留现有列表行为，但详情必须重新对齐当前结果。

## 范围与约束

- 不修改 `WeChatManagement.tsx` 的最终版结构和交互。
- 主要改动集中在 `AccountsAndResourceCenter.tsx` 的详情面板和详情选择逻辑。
- 尽量复用现有回调、确认弹窗、审批流、变更日志和类型专属数据组件。
- 不改变账号资产数据模型，不新增后端接口。

## 验证标准

- 点击“全部”后，右侧不再固定显示抖音资源，且显示的资源属于当前左侧筛选结果。
- 右侧顶层标签为“账号资料 / 绑定分配 / 运营数据 / 个人安全”。
- 底部不再平铺旧版全部按钮，仅显示“编辑 / 发起交接”，并可从更多操作触发其他动作。
- 企业微信、手机号、邮箱、媒体账号详情仍能展示对应字段和运营数据。
- 个人微信页面保持原样。
- `npm run build` 与 `npm test` 通过。
