# 会员个微/企微自动化关系建立设计

日期：2026-10-12

## 1. 背景与目标

经营工作台的首轮目标是帮助工作人员快速完成新会员的关系建立与深度登记：让会员完成应关注的官方账号、应添加的服务人员账号以及必要的社群进入，并把每次执行、AI判断和人工复核沉淀为可追溯的关系数据。

个微和企微的“添加”不是单纯的人工备注，而是一次真实的自动化执行动作。工作人员每点击一次，就创建并执行一次独立任务。自动化服务负责执行，AI负责判断执行结果和关系结果，人工负责复核与修正，工作台负责维护最终关系状态、次数、风险和后续运营动作。

本设计覆盖：

- 个微主动添加；
- 企微引导添加；
- 自动化任务创建与状态回写；
- AI结果判断；
- 人工复核和标识；
- 添加次数、失败原因、风险和关系深度；
- 与会员首轮登记、激活、升级目标、消费计划、关系链的衔接。

不在本阶段实现具体微信客户端自动化程序或AI模型本身，工作台通过已存在的自动化API完成调用和结果接收。

## 2. 核心原则

### 2.1 一次点击对应一次真实任务

每次点击添加都创建唯一任务，不能只增加一个计数。任务必须能追溯到会员、关系角色、目标账号、执行账号、执行人员、添加方式和结果。

### 2.2 执行结果与关系结果分离

自动化执行成功只表示动作完成，不代表会员已经通过好友申请。系统分别记录：

- 自动化执行状态；
- AI判定状态；
- 人工复核状态；
- 最终会员关系状态。

### 2.3 自动化、AI、人工各司其职

- 自动化：执行添加动作并回传任务结果；
- AI：识别是否发起申请、是否通过、是否失败及失败原因；
- 人工：确认、修正、补充备注和决定是否继续尝试；
- 工作台：沉淀关系历史并生成下一步动作。

### 2.4 不覆盖历史

新的执行结果只新增任务和日志，不覆盖历史尝试。会员当前状态由最新有效结果和人工确认共同决定。

## 3. 业务对象

### 3.1 关系角色

首轮关系建立对象包括：

- 服务官个微；
- 服务官企微；
- 班主任个微；
- 班主任企微；
- 官方公众号；
- 官方小程序；
- 官方视频号；
- 会员服务群。

本设计重点实现前四类个微和企微添加，关注和入群沿用现有操作模型，但统一进入关系记录和运营记录。

### 3.2 自动化任务

```ts
type AutomationTaskStatus =
  | "待执行"
  | "执行中"
  | "执行成功"
  | "执行失败"
  | "执行超时"
  | "执行中断"
  | "已取消";

type AiReviewStatus =
  | "待识别"
  | "AI确认成功"
  | "AI确认失败"
  | "AI疑似成功"
  | "AI疑似失败"
  | "AI无法判断";

type HumanReviewStatus =
  | "待人工复核"
  | "人工确认成功"
  | "人工确认失败"
  | "人工修正为成功"
  | "人工修正为失败"
  | "无需复核";
```

任务至少包含：

- taskId；
- memberId；
- relationshipAccountId；
- relationshipRole；
- channel：personal 或 enterprise；
- method：group、search、qr 或 enterprise_add；
- operatorAccountId；
- operatorId；
- createdAt；
- startedAt；
- finishedAt；
- automationStatus；
- aiReviewStatus；
- humanReviewStatus；
- result；
- failureReason；
- humanNote。

### 3.3 最终关系状态

```text
未添加
已申请
已通过
已拒绝
已拉黑
无法添加
多次未通过
```

最终关系状态不能由自动化执行状态直接替代。例如，自动化执行成功、AI判断为“已发出申请”时，最终关系状态只能更新为“已申请”，而不是“已通过”。

## 4. 页面信息架构

会员详情首屏按运营顺序组织：

### 4.1 运营判断区

显示：

- 会员姓名、会员等级、平台身份；
- 当前会员阶段；
- 会员价值；
- 关系完成度；
- 当前风险；
- 当前主任务。

关系完成度示例：`5/8`。当前主任务示例：`完成班主任企微添加`。

### 4.2 首轮登记区

字段分组：

- 基础资料：姓名、微信昵称、微信号、手机号、性别、城市、职业；
- 会员背景：身份、行业、加入原因、当前需求、项目经验；
- 会员意向：加入目的、当前意向、升级意愿、消费偏好；
- 运营标签：新会员、高影响力、高价值客户、潜在升级、待回访、社群活跃、沉默会员、高风险关系；
- 分类结果：会员类型、运营价值、服务优先级、服务归属人、班主任、首轮运营策略。

### 4.3 关系建立区

每个关系对象展示：

- 关系角色；
- 目标账号；
- 执行人员；
- 当前最终关系状态；
- 自动化执行次数；
- 成功次数；
- 失败次数；
- 连续未通过次数；
- 最近执行时间；
- 最近结果；
- 风险等级；
- 主操作按钮；
- 查看历史入口。

### 4.4 激活、目标、购物清单和关系链

关系建立完成后，继续在会员详情中提供：

- 激活行为和首次触达记录；
- 注册天数、升级目标、消费目标和截止日期；
- 推荐购物清单及转化状态；
- 推荐人、服务官、班主任、项目负责人、订单跟进人、售后负责人和社群管理员。

这些模块与自动化添加任务通过会员关系状态、运营阶段和下一步动作连接，不在添加弹窗中一次性展开。

## 5. 个微添加交互

### 5.1 打开流程

点击“服务官个微”或“班主任个微”的“添加”后，打开个微添加窗口，展示会员、目标关系、执行账号、执行人员、会员微信号、城市、所属群和当前历史摘要。

### 5.2 添加方式

支持：

- 从所属群添加；
- 搜索微信号添加；
- 通过二维码添加。

工作人员选择方式并点击执行后，前端调用个微自动化任务创建接口。

### 5.3 创建任务

```ts
createPersonalAddTask({
  memberId,
  memberWechat,
  operatorAccountId,
  relationRole,
  method,
  groupId,
  qrCode,
});
```

返回任务ID后，页面立即展示：

- 任务编号；
- 待执行或执行中的状态；
- 执行账号；
- 创建时间；
- 查看任务详情入口。

每次再次点击“再次添加”都创建新任务，不复用旧任务。

## 6. 企微添加交互

### 6.1 打开流程

点击“服务官企微”或“班主任企微”的“添加”后，打开企微添加窗口，展示会员、企业微信账号、服务人员、会员微信号、当前关系状态和历史执行摘要。

### 6.2 操作内容

支持：

- 发起企微添加；
- 复制会员微信号；
- 打开企微添加引导；
- 查看历史任务。

点击“发起企微添加”调用：

```ts
createEnterpriseAddTask({
  memberId,
  memberWechat,
  enterpriseAccountId,
  relationRole,
  operatorId,
});
```

企微与个微采用同样的任务、AI判断和人工复核链路。

## 7. 状态回写流程

```text
创建任务
→ 自动化任务待执行
→ 自动化执行中
→ API回传执行结果
→ AI识别结果
→ 待人工复核或无需复核
→ 更新最终关系状态
→ 更新统计、风险和下一步动作
```

API支持完整任务创建、状态查询、结果回调和AI判定结果回写，因此优先采用回调更新，查询接口作为页面打开时的补偿校验和异常恢复机制。

前端需要处理：

- 重复回调幂等；
- 回调晚于页面关闭；
- 任务状态回退保护；
- 任务执行失败；
- AI无法判断；
- 人工复核后不被后续普通回调覆盖。

## 8. 人工复核

当AI结果为疑似成功、疑似失败或无法判断时，任务进入“待人工复核”。页面提供：

- 确认已申请；
- 确认已通过；
- 确认未通过；
- 确认被拒绝；
- 确认已拉黑；
- 标记无法添加；
- 标记需要再次处理。

人工补充字段：

- 人工判断结果；
- 失败原因；
- 备注；
- 是否继续尝试；
- 下一次处理时间；
- 转交人员。

失败原因使用固定选项：

- 微信号不存在；
- 搜索不到会员；
- 会员拒绝；
- 会员拉黑；
- 账号异常；
- 自动化执行失败；
- 会员未响应；
- 无法确认；
- 其他。

人工确认结果优先级高于普通AI回写，但仍保留AI原始判定。

## 9. 统计、风险与关系深度

关系对象需要展示：

- 总执行次数；
- 成功次数；
- 失败次数；
- 待复核次数；
- 连续未通过次数；
- 最近执行时间；
- 最近失败原因。

关系深度分级：

```text
L0：未执行
L1：已执行但未确认
L2：已申请
L3：已通过一个服务账号
L4：服务官和班主任关系均已通过
L5：核心账号、官方平台和社群关系基本完成
L6：已互动并产生消费
L7：持续复购或主动推荐
```

连续未通过次数达到3次时，生成关系风险预警，并建议：

- 更换添加方式；
- 转交其他服务人员；
- 人工联系；
- 暂停自动化尝试。

## 10. 按钮状态

- 无历史任务：`添加`；
- 有任务执行中：`执行中`；
- AI分析中：`AI识别中`；
- 待人工确认：`待复核`；
- 已申请：`再次添加`；
- 已通过：`已通过`，默认不允许重复添加，但可查看记录、人工修正或重新发起；
- 多次失败：`风险处理`。

正在执行的同一关系任务需要防止误触重复提交；明确点击“再次添加”时允许创建下一条任务。

## 11. 数据流和接口边界

会员页面只负责：

- 组装任务参数；
- 调用自动化服务；
- 展示任务状态；
- 接收任务回调；
- 发起人工复核；
- 更新会员关系摘要和运营记录。

自动化服务负责：

- 个微或企微动作执行；
- 执行状态回传；
- 执行证据或结果回传。

AI服务负责：

- 识别执行结果；
- 给出AI判定和置信结果；
- 提供失败原因建议。

推荐的前端服务边界：

```ts
type RelationshipAutomationService = {
  createPersonalAddTask(input: PersonalAddTaskInput): Promise<AutomationTask>;
  createEnterpriseAddTask(input: EnterpriseAddTaskInput): Promise<AutomationTask>;
  getTask(taskId: string): Promise<AutomationTask>;
  confirmTaskResult(input: HumanReviewInput): Promise<RelationshipResult>;
  cancelTask(taskId: string): Promise<void>;
};
```

## 12. 实施阶段

### 第一阶段：自动化关系闭环

- 个微添加调用API；
- 企微添加调用API；
- 每次点击创建独立任务；
- 展示执行状态；
- 接收AI判定；
- 人工复核和修正；
- 更新最终关系状态、次数、失败原因和日志。

### 第二阶段：首轮登记

- 基础资料；
- 会员背景；
- 加入目的；
- 需求意向；
- 会员分类；
- 服务人员和班主任分配。

### 第三阶段：激活和运营目标

- 注册天数；
- 激活行为；
- 升级目标；
- 消费目标；
- 购物清单；
- 下一步动作。

### 第四阶段：关系链服务

- 关系角色；
- 订单自动分派；
- 服务任务；
- 交接记录；
- 关系链日志。

## 13. 验证标准

### 自动化任务

- 点击一次只创建一条任务；
- 连续点击三次能看到三个独立任务；
- 个微和企微参数分别正确；
- 任务ID、执行账号和执行人员可追溯。

### 结果回写

- API成功、失败、超时和中断状态均可展示；
- AI结果能进入正确状态；
- AI无法判断时进入人工复核；
- 人工确认后更新最终关系状态；
- 人工确认结果不会被普通重复回调覆盖。

### 运营数据

- 添加次数、成功次数、失败次数准确；
- 连续未通过达到阈值后生成风险提示；
- 历史任务、失败原因和人工备注可查看；
- 关系完成度和当前主任务随结果更新。

### 兼容性

- 保留现有表格布局；
- 保留状态下拉、操作次数和日志入口；
- 关注、入群等非添加动作继续可用；
- API异常时不丢失人工登记能力。
