# 跨页面右侧详情与配置列设计规格

日期：2026-10-07

## 目标

将后台资源、任务、配置和数据页面统一为“当前范围 + 主内容 + 当前对象详情/配置”的交互框架。用户点击列表行、树节点或任务后，右侧区域立即展示同一对象的状态、归属、关系和可执行动作，减少重复跳转和上下文丢失。

本次规格只覆盖后台 PC 页面与移动端响应式行为，不改变既有业务数据模型、权限模型和导航入口。

## 适用范围

首批页面：

- `WeChatManagement`
- `CommunityManagement`
- `AccountAssets`
- `CustomerService`

后续迁移页面：

- `GroupAssignment`
- `Tickets`
- `ApprovalCenter`
- `Orders`
- `ProjectResourceConfig`
- `CityBranch`
- `ReportCenter`

任务工作台、报表看板和复杂配置页不强行套用资源列表布局；它们只复用详情区域的视觉和交互约定。

## 统一布局

桌面端资源类页面采用：

```text
页面标题与当前项目范围
├── 页面操作区：搜索、筛选、新建、批量操作
└── 主区域
    ├── 左侧可选导航或筛选区（按页面需要）
    ├── 中部列表、表格或卡片
    └── 右侧对象详情列
```

右侧详情列为固定宽度、独立滚动区域，列表仍保持可见，便于反复对照。没有选中对象时展示轻量空状态和选择提示；不会展示与当前选中对象无关的固定信息。

移动端将右侧详情列转换为右侧抽屉或页面内覆盖层，点击列表行打开，关闭后回到原列表滚动位置。复杂连续操作仍使用已有 Sheet，新增、编辑和确认继续使用 Dialog。

## 详情列内容契约

所有资源详情列按以下顺序组织，页面可按对象类型隐藏不适用区块：

1. 标题区：对象名称、类型、关闭按钮、状态标签；
2. 核心摘要：当前项目、负责人/保管人、风险状态；
3. 关键指标：对象相关的数量、容量、最近活动或更新时间；
4. 关系区：关联账号、群、人员、项目或审批；
5. 配置区：当前可编辑配置的摘要和入口；
6. 操作区：编辑、交接、查看二维码、归档、跳转等动作；
7. 最近记录：仅展示已有数据中的最近状态或审批信息，不虚构历史记录。

所有字段必须有明确的空状态文案，禁止显示空字符串、`undefined` 或无语义占位。

## 首批页面行为

### 微信管理

列表行选中微信账号后，右侧显示：账号标识、生命周期、账号状态、风险、当前项目、运营负责人、会员负责人、好友数、群数、认证和养号门槛、绑定群与二维码入口。编辑使用 Dialog；交接、群绑定等连续操作使用 Sheet；归档前保留现有确认流程。

### 微信群管理

选中群后，右侧显示：群名称、群类型、项目、城市、群主/服务官、状态、容量、成员统计、绑定微信、二维码和最近运营信息。成员名单和连续运营动作保留在 Sheet 或现有操作区，不将大规模成员表塞入详情列。

### 账号资产中心

保留现有总览列表与选中状态，统一详情样式并补充资源风险、项目归属、关联注册账号和配置入口。手机号、微信号、媒体账号、邮箱及其他账号使用同一摘要契约，但根据类型显示对应关系区。编辑使用 Dialog，交接使用 Sheet。

### 客服与服务资源

选中员工后，右侧显示：姓名、标准角色、启用状态、服务区域、所属项目、管理微信数、管理群数、企业微信/QQ信息、二维码和待办关系。角色与权限编辑使用 Dialog，资源绑定和交接使用 Sheet，密码等敏感字段只显示配置状态，不直接回显明文。

## 项目范围

页面顶部继续继承 `PCLayout` 提供的当前项目上下文。右侧详情中的项目、统计和关联关系必须与当前范围一致；当页面支持“全部项目”时，详情明确标识跨项目范围。切换项目后清除不属于新范围的选中对象，避免显示旧项目详情。

## 交互状态

每个页面至少维护一个选中对象标识和一个派生详情对象：

```text
selectedId → selectedEntity → detail panel
```

点击同一行再次点击时关闭详情；点击另一行立即切换，不产生额外导航。详情内操作成功后通过现有 `flm:ui-feedback` 反馈，并刷新列表或当前详情数据。跨模块跳转继续使用现有 `flm:navigate` 事件。

## 视觉与可访问性

复用现有 `S` 主题、边框、圆角和状态标签，不新增独立主题。详情列使用语义化 `aside` 与可识别的 `aria-label`；可点击列表行提供键盘焦点和明确选中状态。移动端抽屉必须可关闭，焦点不应落到被遮挡的列表内容上。

## 验证要求

实现后必须完成：

- 现有 Vitest 测试全部通过；
- `npm run build` 通过；
- `git diff --check` 通过；
- 首批四个页面分别验证默认空状态、点击选中、切换对象、关闭详情、移动端详情抽屉；
- 验证当前项目切换后详情不会残留旧对象；
- 验证敏感字段没有明文出现在详情列或浏览器可见文本中。

## 非目标

本阶段不重写后端数据源，不抽象出与现有主题冲突的全局状态管理，不将所有页面改造成相同三栏，不新增无数据支撑的操作历史，也不处理与本次详情框架无关的公共资源清理或大型 bundle 优化。
