# 代理 / 团长层级可见范围设计

## 目标

在现有代理与团长工作台能力继承基础上，补充发展关系、推荐关系和社群数据可见范围，避免使用“团队”一词混合直属归属、发展、推荐和运营责任。

## 关系定义

- 直属归属：团长只归属一个直属代理；代理可管理自己的直属团长。
- 发展关系：某个代理发展下级代理，或代理及其下级代理发展团长。发展关系用于组织层级和经营概览，不改变团长的唯一直属归属。
- 推荐关系：用户通过推荐行为产生的关系，单独记录推荐来源，不等同于发展关系，也不自动产生库存、履约或管理权限。
- 运营关系：用户直接负责运营的社群。代理和团长都可以运营自己的社群。

## 代理可见范围

代理工作台提供三个范围入口：

1. 我的社群：可查看自己直接运营的社群、成员明细、内容、活跃度、跟进和成交服务。
2. 发展网络：可查看自己发展的代理；可查看下属代理发展的团长基础资料、状态和经营聚合；可查看下属团长社群数量、成员数和成交聚合。下属代理及其团长默认只读，不开放库存、发货、售后明细。
3. 推荐网络：可查看自己推荐的人及其推荐状态、基础资料；可查看推荐人发展的团长数据聚合，并明确显示“推荐关系”。

代理自己的直属团长管理继续使用现有团长模块，直属管理和发展网络分开呈现。

## 团长可见范围

团长工作台提供两个范围入口：

1. 我的社群：可查看自己直接运营的社群成员明细、内容、跟进和推广转化。
2. 我的推荐：可查看自己推荐的人、推荐状态和基础资料；可查看推荐人发展的团长数量、状态和贡献等聚合数据。

团长不可见代理库存、采购、发货、售后和经营后台；订单只展示与本人相关的路由状态。团长不可查看非本人推荐链条下的其他社群和人员明细。

## 页面呈现

- 每条数据展示关系标签：直属管理、发展关系、推荐关系、只读聚合。
- 代理默认进入“我的社群”，避免默认把发展网络误认为自己的直接运营数据。
- 统计卡片分开显示直接运营数据和发展网络聚合数据，不做无标签合计。
- 代理的直属团长管理与发展网络分开；团长的推荐网络与自己的社群分开。
- 移动端保持现有“社群、团长、履约、经营、推广”与“社群、推广、订单、佣金”角色导航，不新增破坏现有导航的一级模块；范围切换放在对应模块内部。

## 数据模型方向

新增独立的移动端网络范围模型，不把递归可见范围塞入 D1-D5 等级配置：

```ts
type MemberNetworkScope = {
  selfId: string;
  role: "agent" | "leader";
  directCommunityIds: string[];
  developedAgentIds: string[];
  developedLeaderIds: string[];
  recommendedMemberIds: string[];
  aggregateCommunityIds: string[];
  maxDepth: number;
};
```

关系记录应至少区分 relationType：`direct_ownership`、`development`、`recommendation`、`operation`。范围计算只返回当前身份允许的对象和字段；页面不通过隐藏 DOM 代替权限控制。

## 履约与经营边界

- 代理仍负责进货、库存、订单履约、发货、物流和售后。
- 团长成交订单自动路由到直属代理库存，团长只看订单状态和自己的佣金相关信息。
- 发展网络和推荐网络只扩展可见的组织或聚合数据，不改变库存和履约责任。
- 历史订单继续按下单时的生效规则结算。

## 验证标准

- 代理能区分自己的社群、发展网络和推荐网络。
- 团长能区分自己的社群和推荐网络。
- 代理可见下属代理、下属团长及社群聚合，但不能进入下属代理履约后台。
- 团长不能看到代理库存、非本人推荐链条社群和无关团长明细。
- 页面中的直属、发展、推荐和只读标签清晰可辨。
- 现有代理 / 团长导航、角色能力继承和历史身份迁移不被破坏。
