# 聚域身份编码与多重身份展示设计

## 1. 目标

统一会员、渠道、供应商、服务人员和运营人员的身份表达，避免将会员等级、关系角色、业务权限和组织身份混在同一个标签中。

本设计覆盖关系链、会员列表、渠道分发、账号资产和供应商履约等页面的身份展示规则。

## 2. 身份编码体系

| 编码 | 身份类型 | 示例 |
| --- | --- | --- |
| V1-V5 | 零售会员 | V3 · PRO会员 |
| D1-D5 | 渠道 / 分销 | D2 · 分销员 |
| G1-G5 | 供应商 | G3 · 核心供应商 |
| S1-S5 | 服务人员 | S2 · 服务老师 |
| Y1-Y5 | 运营人员 | Y2 · 项目运营 |

编码是身份等级的稳定标识；展示名称可以随业务配置调整，但编码前缀和等级序列保持不变。

## 3. 身份字段模型

身份信息拆分为以下概念：

- `identityType`：身份类型，如 `member`、`channel`、`supplier`、`service`、`operator`。
- `identityCode`：身份等级编码，如 `V3`、`D2`、`G3`、`S2`、`Y2`。
- `identityName`：等级名称，如 `PRO会员`、`分销员`。
- `relationRole`：当前关系中的角色，如 `会员推荐人`、`群主`、`服务老师`。
- `scopes`：身份生效范围，包括项目、区域、平台或生态。
- `status`：身份状态，如有效、待生效、已停用。

同一人员可以拥有多个身份，但不同身份必须分别记录，不能合并为一个字符串。

## 4. 主身份判定

主身份由当前业务场景决定，不按身份数量或全局权限固定排序：

| 业务场景 | 主身份前缀 |
| --- | --- |
| 经营工作台、会员关系链 | V |
| 渠道分发与分销 | D |
| 供应商与商品履约 | G |
| 服务、工单、社群陪伴 | S |
| 系统运营、项目管理、平台治理 | Y |

当前项目或当前页面范围内的有效身份优先于其他项目身份。同一身份类型存在多个等级时，展示当前范围内最高有效等级，详情保留完整变更记录。

## 5. 关系链展示

### 5.1 节点

头像底部展示当前场景下的主身份编码：

```text
头像
 V3
皮卡丘
会员推荐人
会员 · PRO会员
```

节点旁边展示姓名和关系角色；第二行展示身份类型与等级名称。身份等级不再与关系角色混用。

### 5.2 多重身份

不在头像底部堆叠多个编码。存在其他有效身份时，使用主编码加数量：

```text
V3 +2
```

其中 `V3` 是当前主身份，`+2` 表示还有两个其他有效身份。点击或查看详情后展开完整身份列表。

### 5.3 空分支

空分支不显示身份编码，只显示分支状态和添加动作，例如：

```text
会员产品 · 空分支 · 添加成员
```

## 6. 详情面板

右侧详情至少包含：

### 当前身份

- 身份编码
- 身份类型
- 等级名称
- 当前关系角色
- 生效范围

### 其他身份

逐项展示其他有效身份的编码、类型、名称、范围和状态，例如：

```text
D2 · 渠道 · 分销员 · 北京渠道 · 有效
S2 · 服务 · 服务老师 · V001军师 · 有效
```

### 关系信息

- 当前关系路径
- 上级 / 下级数量
- 所属项目和区域
- 微信号及账号资产关联

## 7. 颜色与视觉规则

- V：酸柠绿
- D：蓝色
- G：橙色
- S：紫色
- Y：深色
- 空分支：灰色，不使用身份色

编码标签使用低饱和背景色，保证在头像和关系树紧凑布局中可读，不使用多个高对比标签同时争抢注意力。

## 8. 落地范围

第一阶段统一应用到：

1. 经营工作台关系链
2. 会员列表与会员详情
3. 渠道分发与分销页面
4. 账号资产中心
5. 供应商与商品履约页面

第一阶段先完成共享类型、编码元数据、关系链和会员详情展示；其他页面复用同一套身份格式化规则。

## 9. 验证标准

- 关系链头像底部显示主身份编码。
- 会员、渠道、供应商、服务和运营编码可区分。
- 多重身份不发生标签堆叠，详情可查看全部有效身份。
- 关系角色与身份等级独立显示。
- 当前场景切换后主身份编码随场景变化。
- 空分支不显示虚假身份编码。
- 现有关系链搜索、筛选、节点详情和业务操作台不受影响。
