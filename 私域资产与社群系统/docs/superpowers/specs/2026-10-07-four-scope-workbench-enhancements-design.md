# 四类经营工作台增强设计：轻量运营闭环层

- 日期：2026-10-07
- 状态：已获用户确认，待实施计划
- 范围：任务闭环、项目启动配置、动态指标、窄屏体验

## 1. 背景与目标

现有四类经营工作台已经具备对象主表、下一步动作、统一操作台、任务中心、账号与入群操作、操作日志和右侧档案。本阶段不重做既有工作台，而是在现有前端状态模型上增加一层轻量运营闭环，使“下一步动作”可以被执行、跟踪和回写。

本阶段目标：

1. 下一步动作可以直接形成关联业务对象的任务；
2. 待启动项目可以通过配置表单进入运营中状态；
3. 社群和项目指标来自统一计算口径，并区分待配置、暂无数据和真实零值；
4. 四类工作台在窄屏下仍能查看关键字段、执行动作和打开档案。

本阶段不引入后端接口，不恢复已删除的会员洞察模块，不修改 `EcosystemManagement.tsx`、`PCLayout.tsx` 和 `projectGroupRules.ts` 中与本阶段无关的用户修改。

## 2. 方案选择

采用方案 A：在现有状态模型上增加轻量运营闭环层。

任务、项目配置和指标计算优先在现有工作台组件和数据配置之间建立小范围状态连接，避免对 `PushTasks` 或整套业务数据模型做大范围重构。指标计算使用纯函数，任务和配置使用组件已有的 React 状态管理，后续如接入后端时可以替换持久化边界而不改变展示口径。

## 3. 任务闭环

### 3.1 任务模型

任务至少包含：

- 唯一任务标识；
- 对象类型：会员、社群、项目或代理；
- 对象标识和对象名称；
- 来源工作台；
- 来源动作；
- 任务标题；
- 任务类型；
- 负责人；
- 优先级；
- 截止时间；
- 状态：待处理、进行中、已完成、已暂停、已取消；
- 创建时间、更新时间；
- 结果说明。

对象标识优先使用已有的稳定字段：会员使用 rank，项目和社群使用已有行标识或标准名称，代理使用 `agentId`。如果当前数据没有单独 ID，则使用工作台类型与标准名称组成稳定的前端关联键。

### 3.2 创建流程

点击任一行的 `nextAction` 后：

1. 选中当前行；
2. 打开统一操作台；
3. 根据动作映射默认任务类型和任务标题；
4. 填充业务对象、负责人、优先级和默认状态；
5. 用户确认后创建任务；
6. 在任务中心显示该任务，并写入操作记录。

同一对象、同一来源动作存在未完成任务时，不重复创建，而是定位已有任务并提示用户继续处理。

### 3.3 完成与回写

任务状态改变为已完成时，允许填写结果说明，并更新当前对象的运营阶段或下一步动作。无法安全推断业务结果时，只写入任务结果和操作记录，不强行修改业务指标。

已有账号添加、状态确认、入群、关系处理和日志操作继续使用原有函数和日志结构；任务闭环只增加关联，不替换这些能力。

## 4. 项目启动配置

### 4.1 配置字段

项目配置表单位于统一操作台的项目配置入口，包含：

- 项目负责人；
- 服务人员；
- 项目账号；
- 代理规则；
- 会员入口；
- 关联社群；
- 启动备注。

字段值优先复用已有项目、服务人员和社群数据，不复制 `projectGroupRules.ts` 的规则定义。

### 4.2 校验与保存

保存前校验：项目负责人、至少一个服务人员、至少一个会员入口和至少一个关联社群。项目账号和代理规则如果当前数据没有可选项，显示待配置状态并允许先保存草稿，不伪造账号或规则。

保存成功后：

- 配置状态变为已配置；
- 项目阶段从待启动变为运营中；
- 项目启动任务标记为已完成或同步为已配置；
- 项目指标从待配置状态进入统一计算流程；
- 写入项目配置操作记录。

校验失败时保留表单输入，显示字段级错误，不修改项目阶段。

## 5. 动态指标

### 5.1 统一指标状态

指标计算结果使用明确状态：

- `configured`：配置完整且有可计算数据；
- `no-data`：配置完成但当前没有样本；
- `zero`：有样本且计算结果为真实 0；
- `value`：有样本且结果大于 0；
- `pending`：尚未完成项目或社群配置。

展示层将这些状态映射为“待配置”“暂无数据”“0%”或具体百分比，不以字符串猜测指标状态。

### 5.2 项目口径

```text
授权率 = 已授权会员 / 会员总数
绑定率 = 已绑定账号会员 / 已授权会员
消费转化率 = 已消费会员 / 已绑定账号会员
复购率 = 复购会员 / 已消费会员
```

### 5.3 社群口径

```text
发言率 = 发言会员数 / 成员数
点击率 = 链接点击人数 / 信息有效到达人数
绑定率 = 项目绑定人数 / 成员数
消费转化率 = 消费人数 / 项目绑定人数
```

每项指标保留分子、分母、格式化值和口径文本。分母为 0 时显示“暂无样本”；项目或社群待配置时显示“待配置”；有真实样本且分子为 0 时显示 `0%`。

主表、指标摘要和右侧档案均调用同一计算结果，避免同一指标出现不同口径。

## 6. 窄屏体验

### 6.1 表格

保留宽表横向滚动，不强行把所有字段压缩进单屏。排名、头像和名称列冻结，sticky 列设置不透明背景和明确层级。增加左右边缘渐隐提示和横向滚动提示，使用户知道仍有隐藏字段。下一步动作列必须可滚动到并可点击。

窄屏优先展示名称、阶段、关键数量、核心金额、健康度和下一步动作；次要字段通过行详情或已有档案区域查看，不删除桌面端字段。

### 6.2 档案与操作台

窄屏时右侧档案转换为全宽抽屉或面板，保留概览、项目、社群、订单等已有标签。统一操作台转换为全宽区域，表单控件使用至少可点击的移动端尺寸，并保证保存、完成和取消操作始终可见。

关系链在窄屏时允许横向滚动，节点不被压缩到不可读状态。

## 7. 数据流与边界

```text
ScopeRow / 业务数据
→ 对象识别
→ 下一步动作映射
→ 任务草稿
→ 任务状态与操作记录
→ 结果回写
```

```text
项目配置 / 社群配置 + 原始数量
→ 纯函数指标计算
→ 指标状态、分子、分母、口径
→ 主表、摘要、档案统一展示
```

任务和配置状态在当前页面会话内保持一致。除非已有项目数据明确提供持久化能力，否则不新增 localStorage 或后端写入，避免引入新的数据一致性问题。

## 8. 异常处理

- 缺少对象标识：允许查看动作，但创建任务前提示无法关联并要求补充对象名称；
- 重复未完成任务：定位已有任务，不重复创建；
- 项目配置校验失败：保留输入并显示字段错误；
- 指标分母为 0：显示暂无样本，不显示 NaN 或无穷大；
- 待配置对象：不计算为 0；
- 任务结果不足以推断业务变化：只回写任务结果和日志；
- 窄屏内容溢出：优先通过横向滚动、抽屉和行详情解决，不隐藏核心动作。

自动验证：

- 任务创建、重复任务定位、状态变更和结果回写；
- 项目配置校验、保存和待启动转运营中；
- 项目和社群指标的分母为 0、真实 0、暂无数据和待配置状态；
- 既有账号、入群、关系和操作日志回归；
- 类型检查、测试和构建。

浏览器验证：

- 四类工作台切换；
- 下一步动作创建任务并进入任务中心；
- 项目启动配置完整流程；
- 指标口径和状态展示；
- 390px 左右窄屏下横向滚动、冻结列、档案抽屉和操作台；
- 控制台无错误或警告。
