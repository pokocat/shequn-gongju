# 我的生态层级工作台完整重构规格

## 1. 目标

将超级生态管理员的“我的生态”首页重构为以层级管理为核心的工作台：顶部只保留工作台上下文和全局入口，主体以生态为一级节点、SaaS 合作伙伴与直属超级生态为二级节点，平台与项目通过节点摘要和详情区访问。

## 2. 范围

主要修改 `src/app/components/EcosystemManagement.tsx`：

- `SuperView` 的完整页面结构；
- 主组件顶部工作台栏与对象导航；
- 生态总览数据带；
- 生态层级管理区及选中详情；
- 桌面端双栏与移动端单列响应式布局。

保留：

- `activeTier` 的现有内部值和导航回调；
- 生态、SaaS、平台、项目数据模型；
- 生态、平台、SaaS 创建逻辑；
- 审批、账号、订阅、账单生成逻辑；
- `getPlatformOwnerLabel` 的直属超级生态规则；
- 账号管理、商业与计费、报表入口。

不修改：

- `EcoView`、`SaasView`、`PlatformView`、`ProjectList` 的业务实现；
- 真实 scope 权限算法；
- Vite chunk 体积警告。

## 3. 信息架构

页面由四部分组成：

1. 顶部工作台栏：我的生态、角色、路径、账号管理、商业与计费、身份切换；
2. 对象导航：生态、SaaS 合作伙伴、平台三个入口；我的生态是当前工作台上下文，不作为普通对象 Tab；
3. 生态总览带：生态、SaaS、平台、项目四项数量；
4. 层级管理区：左侧生态树，右侧选中生态详情；移动端为单列折叠详情。

## 4. 层级管理交互

- 默认选中第一个生态，但生态只展示一级摘要，不自动展开二级内容；
- 点击生态行切换展开/收起，并同步右侧详情；
- 生态展开后显示 SaaS 合作伙伴节点和直属超级生态节点；
- SaaS 节点显示其平台数量、项目数量和状态；
- 直属超级生态节点仅在存在无 `partner` 且无 `saas` 的平台时显示，名称固定为“直属超级生态”；
- 生态详情显示公司主体、平台与项目汇总、以及新建 SaaS、查看平台、项目列表、数据报表入口；
- 内部按钮阻止冒泡，避免触发行节点展开；
- 平台与项目不在首页递归铺开，通过详情入口复用已有视图和筛选回调。

## 5. 数据规则

- 生态下 SaaS：`saasList.filter(item => item.eco === eco.name)`；
- 生态下平台：`platformList.filter(item => item.eco === eco.name)`；
- 直属平台：平台同时没有 `partner` 和 `saas`；
- 项目数量：生态下平台的 `projects` 求和；
- 平台归属展示统一调用 `getPlatformOwnerLabel`，不得出现空值、`undefined` 或错误回退；
- 总览带使用当前作用域传入的列表数量，项目使用平台项目数总和。

## 6. 响应式

桌面端：

- 顶部工作台栏单行优先；
- 对象导航横向排列；
- 总览带四列；
- 层级管理区使用 `lg:grid-cols-[minmax(0,1.05fr)_minmax(320px,0.95fr)]` 双栏；
- 右侧详情保持可读且不重复铺陈。

移动端：

- 顶部入口允许换行；
- 对象导航可横向滚动；
- 总览带两列；
- 树与详情单列排列；
- 长描述和公司主体信息放在选中详情中，不造成页面横向溢出。

## 7. 验收标准

- 超级生态首页不再以旧的“统计卡 + 旗下生态列表”作为独立拼接结构；
- 顶部工作台、对象导航、总览带、层级管理区形成统一页面；
- 默认只展开生态层，平台和项目不递归铺开；
- 桌面端存在树形管理区和详情区；
- 390px 宽度无横向溢出；
- 新建生态、SaaS、平台仍可用并保留审批与账号/商业数据副作用；
- 直属超级生态归属显示正确；
- 测试、构建和 `git diff --check` 通过。
