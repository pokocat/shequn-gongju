# 会员运营工作台审查

审查对象：会员运营工作台（会员数据视角）

证据：

- 截图：[01-member-workbench.png](./01-member-workbench.png)
- DOM 快照：[01-dom.txt](./01-dom.txt)

## 结论

当前页面功能覆盖很完整，但信息层级偏多，存在“任务、排行、筛选、关系链、操作台、会员档案”同时争夺注意力的问题。建议先做信息架构收敛，再做视觉细节。

## 高优先级问题

### P0：任务中心和主数据视角职责边界不清

左侧任务中心持续展示任务分类和任务卡片，中间区域又有会员/社群数据与运营操作台。用户需要先判断“我要处理任务”还是“我要看数据”，入口不够明确。

建议：

- 左侧任务中心保留，但默认收起任务详情，只显示待办数量和最近 3 条。
- 顶部三个工作台页签明确为“会员运营 / 推送任务 / 活动运营”，进入推送或活动页后再展开对应任务列表。
- 会员数据页只保留会员筛选、数据表、会员档案。

### P0：筛选工具栏过载

当前一行同时包含搜索、排行时间、年份、月份、应用筛选、重置、标签筛选和数量统计；在窄屏下会横向溢出，且筛选对象混合了排行筛选和画像筛选。

建议：

- 第一行只保留：搜索、时间范围、筛选、重置。
- 第二层使用可折叠的“标签筛选”，默认收起。
- “排行时间”改为统一时间范围选择器，避免“今日排行 / 年份 / 月份”三个时间维度叠加。
- 应用筛选后展示已应用条件 Chips，支持单个删除。

### P1：主表字段语义不稳定

会员表同时出现“排名”和“#1”两列，属于重复字段；“总用户”在会员排行语境下也不易理解。

建议：

- 删除重复的“排名”列，只保留序号。
- 将“总用户”改成明确指标，例如“影响会员数”或“关系链人数”。
- 列标题增加 tooltip 或二级说明，解释“待处理 / 发布 / 完成”的统计周期。

### P1：右侧会员档案过长，首屏信息密度过高

右侧同时展示基础资料、经营摘要、RFM 分层、订单列表和回访入口；在 1440px 宽度下可读，但在窄屏会压缩中间表格。

建议：

- 首屏只保留基础资料、经营摘要、关键指标。
- 订单、回访、历史操作移入档案 Tab，不默认展开全部订单。
- “所在群”点击后跳转到社群数据视角，并自动定位该会员相关群。

### P1：运营操作台与任务中心存在重复动作

左侧任务卡片、中部“问题登记 / 推送任务 / 活动运营 / 朋友圈”都能发起动作，但没有统一的动作记录入口。

建议：

- 统一动作按钮命名为“登记问题 / 创建推送 / 创建活动 / 发布朋友圈”。
- 所有动作提交后进入“操作记录”，并在会员档案中显示最近一条状态。
- 左侧任务卡片只负责进入任务，不再承载第二套创建入口。

## 中优先级问题

### P2：数据视角切换后，筛选状态容易残留

从会员数据切换到社群数据、项目数据时，搜索词、标签和排行时间的语义不同，容易出现旧筛选条件影响新视角。

建议：

- 切换数据视角时清空搜索、标签、时间筛选。
- 每个视角保存独立的筛选状态，返回时恢复该视角最近一次条件。

### P2：左侧任务中心折叠后缺少待办总览

折叠后只剩窄栏按钮，用户看不到待处理数量与最新任务。

建议：

- 折叠态保留一个待办总数徽标。
- 鼠标悬停或点击后显示最近 3 条任务的轻量浮层。

### P2：可访问性和可理解性不足

- 部分图标按钮依赖 tooltip，DOM 中没有统一可读名称。
- 表格横向滚动时，序号和姓名没有冻结。
- 颜色承担了较多状态含义，缺少文字或图标辅助。

建议：

- 所有图标按钮补充 aria-label。
- 冻结排名、头像、姓名三列。
- 预警、进行中、已完成同时使用文字标签，不只依赖颜色。

## 推荐执行顺序

1. 收敛筛选工具栏，拆分基础筛选与标签筛选。
2. 删除会员表重复“排名”列，重新命名“总用户”。
3. 压缩右侧档案首屏，把订单和回访放入 Tab。
4. 统一操作台与任务中心的动作入口和操作记录。
5. 补充切换视角时的筛选重置、冻结列和 aria-label。

## 本轮限制

本轮只做了当前首屏的静态结构和 DOM 审查，没有提交表单、切换视角或验证真实数据接口；因此无法确认筛选条件是否会持久化、操作提交是否真实落库，以及跨视角跳转的实际行为。
